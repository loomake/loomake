# 信頼境界と保護の範囲

Loomakeは、信頼した作業ツリーを対象に、文書・設定・テスト結果を読み、品質コマンド・Git・Claude Code・ghを実行する。仕様ゲートは合意の不足を検出する仕組みであり、悪意あるリポジトリを安全に実行できるようにする仕組みではない。

## 扱う情報と境界

| 対象 | 境界と現在の保護 | 利用時に確認すること |
|---|---|---|
| 要件書・仕様・AGENTS.md | エンジンへの指示に含める。合意とSourceを検査する | 外部から来た文書の指示もレビューする。秘密情報を含めない |
| loomake.config.jsonのcommands | シェルで実行する。完了ゲートが結果を確認する | 信頼したコマンドと依存だけを使う。テストの成功はコマンドの安全性を示さない |
| AIエンジン | 通常は読み書きと指定したコマンドを許可する引数を渡す | エンジン側の権限設定と利用する実行環境を確認する |
| 実行環境と資格情報 | エンジンへ環境変数を引き継ぐ | 必要な範囲の資格情報だけを用意し、隔離環境と外向き通信を環境側で制御する |
| エンジンの変更 | パスをNUL区切りで扱い、設定・現行仕様・テスト削除やskipなどを差分で確認する。エンジンを呼ぶ前後で、gitが使う設定（include の先、利用者全体とシステム全体の設定を含む）とフックのディレクトリを比べ、変わっていればgit add・git commitをせずに止まる | 既存のテストの検査の行（コメントとimportを除いたexpect・assertの呼び出し）を減らす変更と、同じリテラルどうしを比べる検査を足す変更は止める。1行に複数の検査を書き換えるなど、行の数で見分けられない弱体化は検出しない。差分をレビューする |
| 文書とJSONの入力 | 共通readerでファイル・合計・探索を制限し、子のリンクを拒否する | 数値と対象は[resources.md](resources.md)を確認する。全祖先やOSの隔離を検証する仕組みではない |
| 実行時間と出力 | runの残り時間を外部操作へ共有し、Git・ghなどは1操作30秒まで監視する（フックを動かすgit commit・git pushとPRの作成は、runの残り時間まで）。エンジンと共通の外部操作の出力も制限する | 管理する実行記録は既定128MiB/回・履歴512MiBまで。エンジンが直接書くファイルや、実ディスク全体の容量は別に管理する |
| 中断と同時実行 | POSIXではプロセスグループ、Windowsではtaskkillを使う。同じ作業ツリーのrunを排他する | グループから離脱したプロセスの隔離は実行環境で扱う。共有環境は復旧手順の制約を確認する |
| 診断とログ | 既知のトークン形式（OpenAI・Anthropic・GitHub・AWS・npm・Slack・GitLab・Googleのキー、JWT、秘密鍵のブロック、Bearerのトークン）を表示・保存の境界で置換する。stderrはBearerと秘密鍵のブロックもチャンクをまたいで扱い、未確定なASCII単語は4096文字まで保持する。保存するJSON文字列は、改行やUnicodeのエスケープと、出力上限で切れた末尾も扱う | 任意のパスワードや個人情報を識別する仕組みではない。共有前に内容を確認する |
| 証拠とレポート | change・スキーマ・日時・文書のハッシュと生成JSONの上限を検証する。完全に書いた一時ファイルを上書きせず公開する | ハッシュは発行者の署名ではない。要件IDの対応は、テスト内容の十分さを保証しない |
| GitとPR | 検証中のHEAD・ブランチ変更で停止する。整合した直前の証拠だけを再利用し、既存PRを検索する | GitHubでの認証・権限・通信の結果も確認する。ローカルの代替試験と実接続は区別する |

## コードの静的解析

PR・mainへのpush・週1回の定期実行で、CodeQLがJavaScriptとTypeScriptを解析する（[codeql.yml](../.github/workflows/codeql.yml)）。結果はリポジトリのSecurityタブに出る。解析は既知の型の脆弱性を探すもので、エンジンの変更やリポジトリのコマンドの安全性を保証しない。依存の更新はDependabotがPRを作る。

## 権限確認を省略する実行

`--skip-permissions`は、`LOOMAKE_SANDBOX=1`が設定されている場合だけ受け付ける。コンテナ外と判定された通常実行では別途警告し、対話実行で続行を確認する。非対話実行では停止する。この値は利用者の宣言であり、Loomakeがコンテナの隔離やファイアウォールを構築・検証した証明ではない。表示する許可ドメインの一覧も、通信を遮断する実装ではない。利用者が実行環境の通信・ファイルアクセス・資格情報の範囲を設定する。

## 未完了の保護と検証

verify・trace・runの文書とJSONは、ファイル・合計・探索・指示全体の上限を持つ。管理する記録には容量と項目数の上限を設ける。ファイルシステム全体の容量、initなど対象外の入力経路と、環境全体での資源管理は引き続き改善対象である。現在の入力・出力の上限や期限を、すべての資源の上限として扱わない。

セキュリティに関する回帰試験は、特殊文字のパス、子プロセス停止、不正な設定と証拠、診断の置換、二重起動、強制終了、PR公開の再試行を含む。別OS・実エンジン・実際のGitHub接続や、独立したセキュリティ監査の完了はこの記録からは主張しない。最新の根拠と残る項目は[review.md](review.md)に記載する。

脆弱性の報告は[SECURITY.md](../SECURITY.md)、配布元の確認と公開経路は[publishing.md](publishing.md)を参照する。

## フックと子プロセスの保護範囲

Git内部の検査は、フックの通常ファイルとリンク文字列の変更を比較する。リンク先の内容と、フックから呼び出すコードは検査の対象外である。既存のフックと設定した品質コマンドは利用者の権限で実行するため、利用者が内容と依存先を信頼して確認したものを使う。フックのディレクトリにFIFO・ソケットなどの特殊ファイルがある場合は、内容を開く前に対象と理由を示して止まり、そのタスクをコミットしない。停止時もエンジンの変更と特殊ファイルを残す。

POSIXでは、エンジンの通常終了後にも、同じプロセスグループに残る子を停止してから呼び出しを終える。終了要求を無視する子は猶予後に強制終了する。この保証は同じPOSIXプロセスグループが対象であり、別のセッションへ離脱した子は対象外である。Windowsでの通常終了後の子に同等の停止を保証するものではなく、既存の明示停止時のtaskkillによる処理を保つ。Linuxの試験を、未実行のWindows・macOSや実Claude・GitHub接続での成功の根拠にはしない。
