# 開発効率の記録の様式

Loomake 自身の change ごとに、事前の人力工数の推定と、Loomake を使ったときの人の実作業時間を手で書く様式（WBS の W0-7、要件定義の FR-49・FR-50・7.8）。集計と `loomake trace record --effort` は W1-9 で実装し、そのときにこの記録を取り込む。

記録は `docs/effort/<対象>.md` に 1 件 1 ファイルで置く（例：`docs/effort/c-001.md`）。この様式を写して書く。

推定は、対象の実装を始める前に書いてコミットする。推定の「最小」「最大」「根拠」は、コミットしたあとに書き換えない。推定が外れたと分かったときも、実績の節のメモに書き、推定は残す。

推定と実績の差は「推定との差」であり、人力で開発した実測との比較ではない。人力で実施した比較タスクの実績があるときだけ、比較の種類を「人力実測あり」にする。

---

# 開発効率の記録：<対象>

## 記録の基本

| 項目 | 値 |
|---|---|
| 対象 | （WBS 5 章の C-00x など） |
| change | （change ID。まだ作っていなければ「未作成」と書き、作ったら書き足す） |
| 比較の種類 | 推定との比較・人力実測なし ／ 人力実測あり |
| 比較方式 | AI なしの人力 ／ 人が AI を操作する方式 |
| 作業範囲 | （推定と実績で同じ範囲。実装に加えて、指示・レビュー・手直し・判断対応を含める） |

## 事前の推定

実装を始める前に書いてコミットし、あとで書き換えない。

| 最小 | 最大 | 根拠 | 推定した人 | 推定した日 |
|---|---|---|---|---|
| （時間） | （時間） | （作業ごとの内訳と、幅の理由） | | YYYY-MM-DD |

## 実績

change を閉じるときに書く。再オープン後の作業は行を足して追記し、前の行は消さない。時間は分か時間で書き、単位を書く。

| 日 | 指示 | レビュー | 手直し | 実行 | 待機 | うち判断根拠を探す時間 | 判断要求 | 試行 | 費用 | メモ |
|---|---|---|---|---|---|---|---|---|---|---|
| YYYY-MM-DD | | | | | | | | | | |

各列の意味は次のとおり。

- 指示：Loomake や AI エージェントへの指示と、質問への回答にかけた人の時間
- レビュー：PR・差分・判定結果を読んで確かめた人の時間
- 手直し：人が自分でコードや文書を直した時間
- 実行：人がコマンドを実行し、結果を見ていた時間
- 待機：AI や CI の実行を待っていて、ほかの作業をしていなかった時間
- うち判断根拠を探す時間：判断を求められてから、必要な仕様・証跡を見つけるまでの時間（要件定義 1.1）。指示・レビューなどの時間の内訳として書き、合計には足さない
- 判断要求・試行・費用：人に判断を求めた回数、runner や AI の試行の回数、実行の費用

## 合計と推定との差

| 人の実作業時間の合計 | 推定に対する削減率の幅 | 比較の種類 |
|---|---|---|
| （指示＋レビュー＋手直し＋実行＋待機） | （1 − 合計 ÷ 最小）〜（1 − 合計 ÷ 最大） | |

## 柱1の計測

[計測項目の定義](../metrics/delivery-metrics.md)に従って書きます。この節は既存の比較方式・比較の種類・推定と実績を置き換えません。LoomakeなしでAIを使った記録も、人力実測がなければ「推定との比較・人力実測なし」のままです。

| 項目 | 値 |
|---|---|
| 比較の組 | （比較する2記録を結ぶID） |
| Loomakeの利用 | あり ／ なし |
| 規模 | （要件の数と要件書の範囲） |

### 項目の記録

状態は記録あり・不明・非該当・観測中のどれかにします。記録ありは値・単位・取得元・観測期間を書き、0を使えるのはこの状態だけです。不明と非該当は値を空にして理由を書きます。観測中は値を空にして観測を終える日を書きます。実測値を埋めていないこの様式自体は、実際の記録として数えません。

| ID | 項目 | 値 | 単位 | 状態 | 取得元 | 観測期間 | 理由 | 観測を終える日 |
|---|---|---|---|---|---|---|---|---|
| M1 | 実装前に見つかった確認事項の数 | | 件 | | | | | |
| M2 | 仕様ゲートで止まった回数 | | 回 | | | | | |
| M3 | マージ後の手戻りの数 | | 件 | | | | | |
| M4 | 1 change あたりの時間 | | (a)分・(b)時間 | | | | | |
| M5 | AI コスト | | （区分に応じた単位） | | | | | |

Loomakeを使わない記録のM2は、値を空、状態を非該当、理由を「仕様ゲートがないため」と書けます。0にはしません。M4は(a)人の実作業と(b)暦時間を分けて値と単位を書き、足しません。M5は区分の違う金額・トークンを合計せず、下の内訳を取得元として示します。

### M3：手戻りの観測

最後のPRをマージした時刻から14日間を観測します。終わるまでは観測中にして終了予定日を書き、同じ原因の修理はPRが複数でも1件と数えます。追加要望は参考として別記し、観測期間の違う記録を同列に比較しません。

### M4：時間の内訳

(a)は既存の実績表の指示・レビュー・手直し・実行・待機を分にそろえて合計します。判断根拠を探す時間は内数のままで、もう一度足しません。(b)は次の時刻の間を時間で記録します。再オープン後は行を追記し、終了を更新します。PR作成からマージまでの時間で代用しません。

| 要件書を読み始めた日時 | 最後のPRをマージした日時 | 開始と終了の取得元 | 再オープンのメモ |
|---|---|---|---|
| | | | |

### M5：AIコストの内訳

区分は実額・推計・定額・トークンのみです。実額はツールの報告したUSD、推計はトークン数×公開単価、定額は契約額で按分せず、トークンのみは入力・キャッシュ書込・キャッシュ読込・出力を分けます。推計には単価の出典と日付を必ず書きます。同じ区分だけを合計し、取得していない分を無料としません。取得範囲はツールと端末を示し、期間はM4(b)とそろえます。

| 区分 | 値と単位 | ツール・端末の取得範囲 | 期間 | 取得元 | 推計の単価・出典・日付 |
|---|---|---|---|---|---|
| | | | | | |

既存の実績表の費用列には要約を書き、詳しい取得元はこの内訳を参照します。日次トークン集計からchangeの費用を推定しません。公開する記録には匿名化した対象名と集計値だけを書き、セッション本文や自由なログを載せません。
