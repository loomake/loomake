SHA-256 は、上のコミットにあるファイル全体のバイト列（取り込み先を示す記載を含む）から取った。旧表のハッシュは取り込み前の本文を対象にしていたため、この表とは対象が異なる。WBS の固定版や移行時の初期状態は書き換えず、現在の作業状況は GitHub Issues で確認する。

実装状態は要件の全文に対して付ける。「実装済み」は基準コミットに該当する実装があるもの（受入検証の成功や WBS の完了を意味しない）、「一部」は流用できる実装・文書があるが不足が残るもの、「未実装」は対応する製品機能がないもの、「要判断」は適用範囲などの判断が残るもの。初回完成の対象外も状態を付け、対象段階で区別する。未マージの品質スキーマと CI 診断は実装済みに数えない。

「衝突する現行 REQ」は `openspec/specs/` と新版の方針が両立せず、変更の際に change で改訂する必要がある箇所を指す。「なし」は不足がないという意味ではない。基準コミットの現行仕様にはない REQ は追加しない。J01〜J08 は WBS v1.4 の決定に従う。J01 の依存予算（REQ-046・047）は main の改訂で整合しており、判断をやり直さない。

## 3. 照合の結果と残る確認

FR-01〜50 の 50 件、NFR-01〜12 の 12 件は、欠落・重複なく対応 WBS・検証方法・対象段階を持つ。ID のない必須事項 26 件も対応付けた。未割り当てはゼロ。これは作業の割り当ての確認であり、製品が要件を満たすという判定ではない。

### 現行仕様との衝突への対応

- J01：REQ-046・047 の依存予算は改訂済み。Zod の導入済み部分と、未マージの quality.yaml スキーマを区別する。

- J04：REQ-148・149 の core 公開は新版の配置と衝突する。W1-4 の change で kit に移し、core の公開 API から外す。

- W3-6：REQ-101 の Codex 拒否を change で改訂してから接続を足す。OpenHands の扱いは O03 で確認する。
