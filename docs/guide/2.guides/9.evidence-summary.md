# 検証の要約と本体の参照

`loomake trace record --change <id>` は、Evidence 2 の既存欄に `summaryVersion: 1` の拡張を加えて記録する。検証結果、実際に検証したコミット SHA、保存した仕様文書は従来どおり残る。要約を追加したコミットの SHA へ置き換えない。

## 要約に残す事実

`execution` は実行 ID、評価器の版、基準のハッシュ、Node・OS・アーキテクチャ、検証前後の時刻を持つ。GitHub Actions の実行 ID と試行番号を環境値から確認できた場合は、最上位の `ci` に記録する。この環境値だけで生成元の真正性を証明したとは扱わない。

コマンド本文と任意のコマンド名は新しい欄に保存しない。`execution.commands` は設定ファイルの raw SHA-256 と出典を持ち、設定省略時は `defaults` とハッシュの `null` を残す。現在の書き手は訪問順を専用に観測していないため、`nameRefs` は `null` と理由を記録する。設定の順序から実行順序を推測しない。

確認できない既知の欄は `null` とし、`gaps` に理由を残す。未確認の件数を 0 で補わない。既存の検証結果や保存文書を含めた全データの秘密情報保護を、この参照欄だけで保証するものではない。

## 本体との照合

`artifacts` はテストレポートの相対パス、加工前の bytes に対する SHA-256 とバイト数を持つ。本体の内容は要約に複製しない。検証時のレポートハッシュと、同じ表現として比較できる記録時のハッシュが異なる場合は、要約を公開せず終了コード 1 を返す。

同じ実行の開始時刻・品質コマンド・レポート構造などを照合できた場合だけ、`sameRun.status` を `verified` とし、観測した 6 種類の件数を残す。この値は全試験の完了、生成元の真正性、品質の合格を保証しない。古い開始時刻、既知の部分出力、不正 UTF-8 などは未確認と理由を残し、元の検証結果を保つ。

現在の `record` は共有保存先へのアップロード・取得を行わない。`availability` は `not-uploaded`、`location`・`expiresAt`・`retrieval` は `null` と理由を残す。共有先から辿れる索引、リリース記録、失敗試行と既存の大きな記録の整理は [Issue #69](https://github.com/loomake/loomake/issues/69) の後続作業である。

## 取得済みの本体を API で照合する

kit の `checkArtifactBody(ref, bytes)` は、渡した `Uint8Array`（Buffer を含む）の view の範囲だけを、参照のハッシュ・バイト数へ照合する。ファイルの取得や品質判定は行わない。

`artifactRetention(ref, policy, now)` は、参照の `location.createdAt` と `expiresAt` から当時の保持期間を `retention` に、明示した現在時刻から期限の状態を `current` に返す。前者は `satisfied`・`insufficient`・`unverified`、後者は `available`・`expired`・`unverified` である。実際の 7 日と方針の 90 日を混同せず、期限切れでも当時の判定を書き換えない。`available` は期限だけの状態で、取得権限や本体の存在を証明しない。

## 旧形式と公開スキーマ

拡張の目印がない Evidence 1・2 は従来どおり閲覧でき、旧記録は書き換えない。拡張の目印が不正な最新記録は終了コード 2 で止め、古い成功記録へ戻らない。

拡張の構造は core の `loadSummarySchemas()` で遅延ロードし、`@loomake/core/schema/summary/evidence-summary-1.schema.json` からも参照できる。既存の 12 本の JSON Schema と Evidence・Report 自体の形式版は変わらない。
