# 静的品質指標の観測

`@loomake/kit` の `observeStaticMetrics` は、品質コマンドが今回出したテスト結果とカバレッジを、製品品質の観測へ変換する純粋関数です。品質基準と実行結果の receipt、本文の SHA-256 を計算する関数を受け取り、`QualityObservation[]` を返します。入力を変えず、ファイルや時計を読みません。

| source | metric | 値 |
|---|---|---|
| `ci.test_report` | `tests_total`・`tests_failed`・`tests_passed` | passed と failed の実施件数。skip・todo・pending は含めない |
| `ci.coverage` | `statements_pct`・`branches_pct`・`functions_pct`・`lines_pct` | 既存の集計が持つ有限の0〜100の割合 |
| `ci.command.<name>` | `error_count` | 既存出力では件数を取得できないため未評価 |

呼出側は、実行前に前回の出力を消し、同じ実行の出力を receipt に集めます。receipt には、テストランナーの名前と版、前後の対象コミットと品質基準のhash、実行時刻、出力を消した事実、コマンド結果、出力の本文・パス・hashを渡します。テストは既存設定のレポート、カバレッジは `.loomake/coverage/coverage-summary.json` を使います。

receipt を渡せるのは、呼出側が実行の完了を確かめた場合だけです。実行を終えたテストに失敗があれば、コマンド結果を `failed` にして実際の件数を観測できます。中断・時間切れ・起動失敗や `bail` による途中停止では、部分的な出力が残っていても receipt に `null` を渡します。この場合の観測は `not_run`・値なしです。純粋関数は実行の完了を調べないため、呼出側でこの区別を確かめます。

対象・品質基準・本文のhashが一致しない、今回の実行時刻の範囲外である、テストを実行できなかったファイルがある、といった場合は測定値にしません。未取得のカバレッジや実施ゼロを、0件の失敗や0%へ置き換えません。

lint・型検査の終了コードはエラー件数ではありません。設定されたコマンドの `error_count` は成功・失敗のどちらでも `unavailable`・値なし、未設定なら `not_run` になります。`nonzero_exit` と非対応の source・metric から観測を作りません。利用時品質へ製品品質の観測を流用しません。

この関数はコマンドの実行・品質判定・保存を行いません。手動の `trace eval` と要求追跡、保存、品質状況レポートは、W1-11の後続changeで追加します。
