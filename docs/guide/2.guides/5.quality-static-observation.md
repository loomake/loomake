# 静的品質指標の観測

`@loomake/kit` の `observeStaticMetrics` は、品質コマンドが今回出したテスト結果とカバレッジを、製品品質の観測へ変換する純粋関数です。品質基準と実行結果の receipt、本文の SHA-256 を計算する関数を受け取り、`QualityObservation[]` を返します。入力を変えず、ファイルや時計を読みません。

| source | metric | 値 |
|---|---|---|
| `ci.test_report` | `tests_total`・`tests_failed`・`tests_passed` | passed と failed の実施件数。skip・todo・pending は含めない |
| `ci.coverage` | `statements_pct`・`branches_pct`・`functions_pct`・`lines_pct` | 既存の集計が持つ有限の0〜100の割合 |
| `ci.command.<name>` | `error_count` | 既存出力では件数を取得できないため未評価 |

呼出側は、実行前に前回の出力を消し、同じ実行の出力を receipt に集めます。receipt には、テストランナーの名前と版、前後の対象コミットと品質基準のhash、実行時刻、出力を消した事実、コマンド結果、出力の本文・パス・hashを渡します。テストは既存設定のレポート、カバレッジは `.loomake/coverage/coverage-summary.json` を使います。

receipt を渡せるのは、呼出側が実行の完了を確かめた場合だけです。実行を終えたテストに失敗があれば、コマンド結果を `failed` にして実際の件数を観測できます。中断・時間切れ・起動失敗や `bail` による途中停止では、部分的な出力が残っていても receipt に `null` を渡します。この場合の観測は `not_run`・値なしです。純粋関数は実行の完了を調べないため、呼出側でこの区別を確かめます。

対象・品質基準・本文のhashが一致しない、今回の実行時刻の範囲外である、テストを実行できなかったファイルがある、といった場合は測定値にしません。未取得のカバレッジや実施ゼロを、0件の失敗や0%へ置き換えません。

lint・型検査の終了コードはエラー件数ではありません。設定されたコマンドの `error_count` は成功・失敗のどちらでも `unavailable`・値なし、未設定なら `not_run` になります。`nonzero_exit` と非対応の source・metric から観測を作りません。利用時品質へ製品品質の観測を流用しません。

この関数はコマンドの実行・品質判定・保存を行いません。手動の `trace eval` は、この関数を使って品質評価と要求追跡、保存を行います。使い方は次の節で説明します。品質状況レポートは、W1-11の後続changeで追加します。

## 手動で評価を保存する

変更をコミットした作業ツリーで、次を実行する。

```sh
loomake trace eval
```

`quality.yaml` と設定済みの品質コマンドを読み、前回のテストレポートと `.loomake/coverage/coverage-summary.json` を消してから、一度だけ実行する。テストの件数・カバレッジを今回の出力から取得し、取得できない値は未評価にする。製品品質と利用時品質は別々に判定する。終了0だけではテスト全件の完了とみなさず、途中停止・保留・件数不整合・未確認の失敗出力は値を付けない。

`reports/quality/history.jsonl` に評価、`requests.jsonl` に受付と到達状態、`attempts.jsonl` に開始後の失敗を追記する。`quality-report.json` は履歴末尾と同じ内容の最新索引である。同じコミットの別試行と翌UTC日の評価も残す。これらはGitで管理する正本なので、内容を確認してコミットする。コマンド自身はステージやコミットを作らない。

有効な未コミットの帳簿追記と索引は次の評価でも許可する。帳簿以外の変更、ステージ済みの変更、既存行の書換え・削除・改名があれば、品質評価を保存しない。固有オプションはなく、既存の `trace report --change <id>` も従来どおり使える。いまはGitリポジトリの最上位をルートにして実行する。サブディレクトリをルートにすると帳簿の追記も汚れと判定され、実行のたびに1を返して失敗試行の行が増える。

| 終了コード | 結果と次の操作 |
|---|---|
| 0 | 評価を保存した。品質判定がFAILや証拠不足の場合も含むため、索引の判定を確認する |
| 1 | 作業ツリーが汚れているか実行中に対象・基準・帳簿が変わった。変更を確認して再実行する |
| 2 | 入力・台帳・保存に問題がある。原本を保持して診断を確認する |
| 3 | 既存ロックのため未受付、実行不能、中断、または実行権を失った。診断と要求・失敗試行を確認する |

最新索引だけの保存に失敗した場合、履歴と古い索引を保持する。有効な履歴を残して再実行すると末尾から索引を復旧し、その要求の評価も続ける。出どころが履歴にない索引や不正な台帳は上書きしない。

`.loomake/quality/eval.lock` がある間は新しい要求を受け付けず3を返す。止まった実行の残りかを利用者が確認し、その実行が終了している場合にだけ手動でロックを消して再実行する。次の実行者が残った要求を回収し、既存の履歴・失敗行を保持する。最初のSIGINT・SIGTERM・SIGHUPは取消を記録し、2回目は即時に終了するためロックが残ることがある。品質コマンドの同期実行中に親だけへ届いた信号は、その実行から戻ったあとで処理する。

FIFOの待機と週次の状況生成は後続の変更で実装する。手動同時要求の受入とW1-11全体の完成は、それらの検証後に判断する。
