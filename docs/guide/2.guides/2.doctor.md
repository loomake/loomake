---
title: doctorで導入と設定を確認する
description: loomake doctor で導入と設定を確かめる方法
---

プロジェクトのルートで`loomake doctor`を実行する。ファイルや設定は変えず、品質コマンドも実行しない。問題は終了コード1、注意だけの場合と問題がない場合は0を返す。注意がある場合も、その項目は確認してから利用する。

## 確認すること

| 対象 | 確認内容 |
|---|---|
| 導入ファイル | loomake.config.jsonの形式、AGENTS.mdが通常のファイル、openspecDirがディレクトリであること |
| 品質コマンド | lint・typecheck・testの設定、単純な呼び出しの実行ファイルが見つかること。POSIXでは実行権限も確認 |
| npm・pnpmのscript | 単純な呼び出しに対応するpackage.jsonのscriptが空でない文字列であること |
| Yarnのscript | ルートにscriptがあれば確認。ない場合は他の解決経路を推測せず注意にする |
| Gitの除外 | テストレポートを除外し、証拠をコミットできる配置であること |
| 追加のCLI | OpenSpec、Claude Code、GitHub CLIの実行ファイルが見つかること |

出力末尾に未確認の範囲を表示する。品質コマンドの成功、テストレポートの生成と内容、認証、ネットワーク接続は調べない。実行ファイルとscriptが存在するだけで、runやPR公開が成功すると判断しない。

## scriptがないと表示されたら

initはLoomakeの設定と規約を配る。プロジェクトの品質コマンドそのものは用意しない。`pnpm test`や`npm test`が設定されていれば、package.jsonのscripts.testが必要になる。

表示されたscripts.testなどの項目と、loomake.config.jsonのcommandsを見比べる。プロジェクトで使っているscriptを設定するか、実際の品質コマンドをcommandsへ記載して、doctorを再実行する。次にverifyで実際の検査を行い、使うテストランナーのJSONレポートをtests.reportへ生成する。doctorはその生成を代わりに行わない。

静的にscriptを調べる対象は、npm run・run-scriptとnpm test、pnpm run・run-scriptとpnpm test・lint・typecheck、Yarn runとYarn test・lint・typecheckの単純な形である。引数を付ける場合、script名の後の`--`以降だけを扱う。workspaceやfilter、対象を変えるオプション、正規表現でのscript選択は未確認の注意にする。npm run envの組み込み処理とYarnのrun-script表記も、scriptを推測しない。

npmのscriptとenvの組み込み処理は[npm run-scriptの公式説明](https://docs.npmjs.com/cli/v10/commands/npm-run-script/)、pnpmのscriptの短縮形は[pnpm runの公式説明](https://pnpm.io/cli/run)、Yarnのscript・依存バイナリ・workspaceの解決は[Yarn runの公式説明](https://yarnpkg.com/cli/run)を参照する。doctorがこれらの解決全体を再現するわけではない。

## 未確認の注意が出たら

環境変数の代入や展開、`&&`などの連結、リダイレクト、コマンド置換を使うコマンドは、シェル全体を解析せず注意にする。引用付きの単純な実行ファイルのパスは扱う。Windowsの単一引用符はシェルの引用と見なさない。

複雑なコマンドは、実際に使うシェルと作業ディレクトリで確認する。必要ならpackage.jsonのscriptへまとめ、commandsには単純なscript呼び出しを記載すると、doctorで存在を確認できる。ただし、script本文の正しさは引き続きverifyで確かめる。

## Gitの診断に失敗したら

Gitの診断全体は30秒までとし、外側に短い共有予算があればそちらを使う。時間切れ・出力超過・中断・Git異常を、Git不存在や未除外と混同しない。診断できなかった項目を確認済みと扱わず、同じディレクトリでgit statusを実行して理由を確認する。既存の設定を直し、doctorを再実行する。詳しい上限は[resources.md](../3.reference/2.resources.md)を参照する。

## 操作試験の再現

リポジトリのルートから、ビルド後に新規の試験先を指定する。

```sh
pnpm build
node openspec/changes/archive/2026-10-24-clarify-doctor-diagnostics/doctor-journeys.mjs .loomake/quality/doctor-trial-new
```

script欠落、未対応のコマンド、壊れたpackage.jsonの3シナリオを、ビルドしたCLIで診断・修正・再確認する。結果、出力、終了コード、ソースと配布用コードのハッシュをresults.jsonへ記録する。[今回の結果](https://github.com/loomake/loomake/blob/main/openspec/changes/archive/2026-10-24-clarify-doctor-diagnostics/results.json)はAI作成の試験で、人の利用者や独立した評価者は含まない。別OSや認証・実際のGitHub接続を確認した結果でもない。
