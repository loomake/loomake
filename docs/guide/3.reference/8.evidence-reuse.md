# 証跡だけの変更で要約を再利用する

`loomake trace reuse` は、HEAD までの各コミットが許可された証跡の追加だけで、要約と外部の信頼値が一致するとき、品質コマンドを起動せずに整合性を記録します。コードや仕様の変更が混ざる場合や、環境・基準が違う場合は、同じ入口で実際に再検証します。要約が改変されている場合は人へ差し戻します。

```sh
loomake trace reuse --change example --summary .loomake/evidence/example/20261106T000000Z-0123456789ab.json --anchor /outside/frozen-anchor.json --json
```

`--summary` は HEAD の tree にある要約の repo 相対パスです。source は信頼値の `sha`、target は HEAD です。信頼値は、呼出側がリポジトリの外で凍結した JSON を用意します。

```json
{
  "summarySha256": "要約の元bytesのSHA-256（小文字64桁）",
  "runId": "CIの実行IDの数字列",
  "runAttempt": "先頭0のない正の試行番号",
  "sha": "検証したsourceの完全な小文字SHA"
}
```

ここに示した文字列は欄の説明です。実際のファイルでは、取得した値に置き換えてください。信頼値の取得元と真正性は呼出側の責任です。この入口が確認するのは、正規化したパスがリポジトリと git common dir の外にあること、最後の要素がリンクでない通常ファイルであること、判定中に bytes が変わらないことです。hardlink と、別の経路でマウントした場所は検出しません。

結果は `reused`・`revalidated`・`returned-to-human`・`stopped` の4種類です。`--json` は結果1つだけを標準出力へ出し、進捗は標準エラーへ出します。再利用と再検証の成功は0、差し戻しと停止は1、使い方の誤りは2、外部操作の期限は3です。再検証では実際の検証の終了コードを返し、`--scope local|ci` がその範囲を指定します。省略すると ci です。使い方の誤りと実行時の失敗では JSON を出しません。

再利用の記録は `.loomake/evidence/<change>/reuse/` に追記します。`verification: integrity-only` と `qualityCommands: not-run` を持ち、信頼値の真正性は `unverified` と記録します。元の要約は書き換えません。この記録は品質の合格や CI の最終合格を表しません。後の再利用の判定根拠にも使いません。必須 CI・完了ゲート・独立レビューを実行し、マージ直前には対象の HEAD でこの入口を再実行してください。

既知の秘密の形を含む change-id・パス・評価器や実行環境の版は、値を置き換えて記録せず、保存前に使い方の誤りとして拒否します。表示上のパスに秘密の形が含まれる場合は `***` となり、元の値へ戻しません。

`@loomake/trace` の同期 API `runReuse` と `reuseRecordProblem`、kit の `readEvidenceRange` と `createGitEvidenceReader` も利用できます。受入試験は、実際に記録した ci 要約と repo 外の凍結 fixture を使います。実運用で信頼値を取得したことや、その真正性を確認したことを示すものではありません。
