# CI 監査項目 2：prepare の重複 build を省く

1. やったこと：監査項目 2 として、CI の quality・Node20・Node22 の prepare に `--skip-build` を付け、直前の明示 build と同じ build を省くようにした。change は ADR 0005 により不要な L2、経路は normal（受入条件が明確な開発基盤の変更）で、設計は AGENTS.md 2 章により省略した。既定の prepare・globalSetup・5 pack・独立 consumer・offline 検査・既存試験と品質設定を保持した。
2. verify の結果：change 指定の仕様・完了ゲートは対象外。新規回帰の 1 件で修理前の失敗を確認し、修理後は新規 6 件を含む関連 62 件と既存配布物 10 件が成功した。lint・型・build・差分の空白検査も成功した。通常の coverage 付き全体試験は 2,475 件成功・既存 8 件保留で、文 95.45%・分岐 90.55%・関数 97.57%・行 98.01% の既存閾値を満たした。
3. 残っている確認事項・仮定：build の呼び出しは各 quality ジョブで 3→2 回、Node20/22 で各 3→1 回になる。pack と consumer 検査は省かず、この回数から秒数を推定しない。Windows の shell 引用は新規試験の mock 側で復元し、同じコマンドと引数を検査するが、実 Windows は CI での確認を残す。
4. 次にやること：全体試験の成功を確認した管理役が、同じ head の必須 5 チェック・全 3 OS・起草者以外の確認・独立 Opus レビューを進める。PR の前後実測がそろうまで、監査項目 2 の採用と全体 CI の短縮を報告しない。
