# 短い入力で初回配布の開発を始めるスキル

1. やったこと：`$delivery` でGoal確認とIssue処理を始めるリポジトリスキルを追加し、既存の開発手順へ呼び出し方を追記した。製品change-id・タスク番号は対象外の開発手順。既存Goalの継続・新規作成と、別Goal・停止中・ツール未対応の場合の終了を分けた。スキル作成だけではGoalも開発も開始しない。
2. verify の結果：製品のverifyは対象外。公式スキル形式検証、文書リンク40件、新規スキル・手順内の相対リンクとdiff --checkが成功。独立した6状況の模擬確認で見つかった終了条件の曖昧さを修正し、2回目の確認で重大な指摘なし。
3. 残っている確認事項・仮定：VS Code上での実際のGoal作成と開発起動は行っていない。Goal操作ツールがない環境では短い /goal の入力が必要。常駐・停止後の自動再開は保証しない。Python検証器のPyYAMLは一時領域だけに用意し、製品の依存や設定は変更していない。
4. 次にやること：PRの必須CIを確認し、承認範囲内で取り込む。スキルを含むブランチの作業フォルダから、Codexで `$delivery` を明示的に呼び出して使う。
