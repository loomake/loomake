# 同じ領域の小さな項目をまとめる手順

本文作成時点の記録。以後のhead別の検証・レビュー・CI・マージ結果は [PR #171](https://github.com/loomake/loomake/pull/171) を参照する。

1. やったこと：依頼1-4の束ね方を記録した。製品・配布物の振る舞いと担当・必要ゲート・反復・マージ条件は不変で、利用者1-4の受入が確定しているため、既存例外へ当たると補助セッションが判断して設計を省略した。利用者の個別承認とは扱わない。根拠と出典はPR本文に残す。
2. verify：初回の作業ツリーと固定headで関連試験が成功した。本文修正後の固定headでの再実行はこれから。通常verify・lint・型・全体試験は未実施、製品spec-only・doneはADR0005により対象外。準備67秒は部分観測で、詳細と各headの証跡はPR本文へ記録する。
3. 確認事項・仮定：追加なし。最初のOpus起動は権限拒否のため未実施とし、参考指摘3件へ対応した。出典リンク、混在する束の扱い、記録の形式を明確にした。履歴はPR本文に残す。
4. 次：修正後の新headで再検証し、worktree内の資料だけを渡して独立最終レビューを再依頼する。CI・自動Codexと合わせ、既存管理役へ取り込み判断を引き継ぐ。補助側はマージしない。
