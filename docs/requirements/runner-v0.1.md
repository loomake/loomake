# run 要件定義書

## 1. 概要

run は仕様ゲートを通った change の tasks.md を AI のエンジンに実装させ、完了ゲートが通るまで直させて、PR を出すところまでを自動で進める。完了したかどうかの判断は kit の verify に任せ、run は「verify が通るまで回す」ことだけを受け持つ。人がやるのは、確認事項への回答と PR のレビューだけにする。

1. 仕様ゲートを実行する。不合格なら始めない
2. change 用のブランチを作る
3. 未完了のタスクを 1 つ選び、エンジンに実装させてコミットする
4. タスクが残っていれば 3 に戻る
5. 完了ゲートを実行する。不合格なら不合格の内容をエンジンに渡して直させ、もう一度実行する
6. 完了ゲートが通ったら、trace の証拠を記録して PR を出す

途中で上限に達したときや、エンジンが質問したときはそこで止まる（3.3）。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | CLI の `loomake run` |
| 対象 | エンジンの切り替え（最初は Claude Code の headless 実行） |
| 対象 | 不正な直し方の検出と停止 |
| 対象 | 実行の記録と再開 |
| 範囲外 | 仕様を決めることと、確認事項に答えること |
| 範囲外 | PR のマージ |
| 範囲外 | 複数の change の並行実行 |

## 3. 機能要件

フェーズが「初版」の行を run の最初のリリースに含める。

### 3.1 実行前の確認

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-PRE-01 | `loomake run --change <id>` を実行したら、最初に仕様ゲートを実行し、不合格なら実装を始めずに不合格の内容を表示すること | 初版 |
| RUN-PRE-02 | 作業ツリーに未コミットの変更があるときは、実装を始めないこと | 初版 |
| RUN-PRE-03 | `--dry-run` で、実行する予定のタスクとエンジンへの指示を表示し、実装はしないこと | 初版 |

### 3.2 実装の繰り返し

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-LOOP-01 | change ごとに `loomake/<change-id>` のブランチを作ること | 初版 |
| RUN-LOOP-02 | tasks.md の未完了のタスクを、上から順に 1 つずつエンジンに渡すこと | 初版 |
| RUN-LOOP-03 | エンジンへの指示に、AGENTS.md、対象のタスク、関係する spec.md と trace.md を含めること | 初版 |
| RUN-LOOP-04 | タスクを終えるたびにコミットし、tasks.md のそのタスクを完了にすること | 初版 |
| RUN-LOOP-05 | すべてのタスクを終えたら完了ゲートを実行し、不合格なら不合格の内容をエンジンに渡して直させること | 初版 |
| RUN-LOOP-06 | `--engine` でエンジンを選べること。初版は `claude-code` に対応する | 初版 |
| RUN-LOOP-07 | エンジンを足すための共通のインターフェースを公開すること | 次 |
| RUN-LOOP-08 | Codex に対応すること | 次 |

### 3.3 止まる条件

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-STOP-01 | 直しの回数が上限（既定 5 回）に達したら止まること | 初版 |
| RUN-STOP-02 | 実行時間が上限（既定 60 分）に達したら止まること | 初版 |
| RUN-STOP-03 | エンジンが仕様にない判断について質問したら止まり、質問を表示すること | 初版 |
| RUN-STOP-04 | 止まったときは、理由・終えたタスク・残ったタスク・最後の検査結果を報告すること | 初版 |
| RUN-STOP-05 | `loomake run --resume` で、止まったところから再開できること | 次 |

### 3.4 不正な直し方の検出

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-GRD-01 | テストファイルの削除と、skip・todo の追加を差分から検出したら止まること | 初版 |
| RUN-GRD-02 | loomake.config.json と、lint・型・テストの設定ファイルの変更を検出したら止まること | 初版 |
| RUN-GRD-03 | `openspec/specs/` と trace.md の変更を検出したら止まること | 初版 |
| RUN-GRD-04 | 止まったときは検出した差分を表示し、人が承認するまで先へ進まないこと | 初版 |
| RUN-GRD-05 | テストの期待値を書き換えた差分を検出し、人の確認を求めること | 次 |

### 3.5 PR

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-PR-01 | 完了ゲートが通ったら、`loomake trace record` を実行してから PR を作ること | 初版 |
| RUN-PR-02 | PR の本文に、change の概要、完了ゲートの結果、要件ごとのテストの一覧を含めること | 初版 |
| RUN-PR-03 | PR は gh CLI で作ること | 初版 |

### 3.6 実行の記録

| ID | 要求 | フェーズ |
| --- | --- | --- |
| RUN-LOG-01 | 実行ごとに、エンジンへの指示・エンジンの出力・各回の検査結果を `.loomake/runs/<実行 ID>/` に保存すること | 初版 |
| RUN-LOG-02 | 記録に API キーなどの秘密情報を含めないこと | 初版 |
| RUN-LOG-03 | 使ったトークン数と費用を、エンジンが返す範囲で記録すること | 次 |

## 4. 非機能要件

| ID | 種別 | 要求 |
| --- | --- | --- |
| RUN-N-01 | 安全 | devcontainer か、それと同等のコンテナの中で動くこと |
| RUN-N-02 | 安全 | エンジンを権限確認なしで動かすときは、許可したドメインのほかへ通信できない環境でだけ実行すること |
| RUN-N-03 | 安全 | コンテナの外で実行しようとしたときは、警告して確認を求めること |
| RUN-N-04 | 依存 | 実行時の依存を `@loomake/core`・`@loomake/kit`・`@loomake/trace` だけにすること（エンジンの CLI と gh を除く） |
| RUN-N-05 | 信頼性 | 中断されたときも、終えたタスクのコミットと実行の記録を残すこと |
| RUN-N-06 | 環境 | Node.js 20.19 以上で動作すること |

## 5. 未決事項

| ID | 関連 | 論点 | 候補 |
| --- | --- | --- | --- |
| RUN-Q-01 | 全体 | パッケージ名を `@loomake/run` にするか `@loomake/runner` にするか（CLI は `loomake run`） | run / runner |
| RUN-Q-02 | 3.3 | 直しの回数と実行時間の上限の既定値 | 5 回・60 分（暫定）/ 実案件で計測して決める |
| RUN-Q-03 | RUN-LOOP-02 | タスクを 1 つずつ渡すか、change のタスクをまとめて渡すか | 1 つずつ / まとめて |
| RUN-Q-04 | RUN-N-02 | 許可するドメインの既定の一覧 | npm・GitHub・エンジンの API だけ / プロジェクトごとに設定する |
