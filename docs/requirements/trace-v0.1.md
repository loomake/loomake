# trace 要件定義書

## 1. 概要

trace は kit が作った trace.md と verify の JSON を読み、「どの要件を、どのテストで、いつ確かめたか」を顧客に渡せる検収レポートにまとめる。確認事項への回答と仮定の承認も、合意の記録として残す。実装を人が行っても AI が行っても、kit と trace だけで「要件、実装、証拠」が一周する。

| 種類 | 内容 |
| --- | --- |
| 入力 | trace.md（要件台帳・確認事項・仮定） |
| 入力 | `loomake verify --done --json` の結果 |
| 入力 | `openspec/specs/` と archive 済みの change |
| 入力 | git のコミット履歴とタグ |
| 出力 | 検収レポート（Markdown・HTML・JSON） |
| 出力 | 証拠の記録（`.loomake/evidence/` に保存する verify の結果） |

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | CLI の `loomake trace record`（証拠の記録）と `loomake trace report`（検収レポート） |
| 対象 | change 単位とリリース単位のレポート |
| 対象 | 合意の記録（回答者・承認者と日付） |
| 範囲外 | テストの実行（kit の verify が受け持つ） |
| 範囲外 | 顧客による承認の操作と電子署名（trace はレポートを渡すところまで） |
| 範囲外 | 見積もりと請求 |

## 3. 機能要件

フェーズが「初版」の行を trace の最初のリリースに含める。

### 3.1 証拠の記録

| ID | 要求 | フェーズ |
| --- | --- | --- |
| TRC-REC-01 | `loomake trace record --change <id>` で `verify --done` を実行し、結果をコミットの SHA・日時と合わせて `.loomake/evidence/<change-id>/` に保存すること | 初版 |
| TRC-REC-02 | 作業ツリーに未コミットの変更があるときは記録せず、理由を表示すること | 初版 |
| TRC-REC-03 | 記録した証拠のファイルを書き換えず、新しい記録を別のファイルとして足すこと | 初版 |
| TRC-REC-04 | 記録ごとに中身のハッシュを保存し、あとから書き換えがないかを確かめられるようにすること | 次 |

### 3.2 検収レポート

| ID | 要求 | フェーズ |
| --- | --- | --- |
| TRC-RPT-01 | `loomake trace report --change <id>` で、要件ごとに出典・対応する Requirement・テスト・最後の検査結果を並べた表を出力すること | 初版 |
| TRC-RPT-02 | 状態が「範囲外」と「既存仕様で充足」の要件も、状態を付けて表に含めること | 初版 |
| TRC-RPT-03 | テストのない要件、最後の検査で不合格の要件、確認待ちの要件があるときは、レポートの冒頭に一覧で示すこと | 初版 |
| TRC-RPT-04 | レポートに、使った証拠の記録（日時・SHA）を記載すること | 初版 |
| TRC-RPT-05 | `--format md\|html\|json` で出力の形式を選べること。初版は Markdown と JSON に対応する | 初版 |
| TRC-RPT-06 | HTML の形式で出力できること | 次 |
| TRC-RPT-07 | `--audience customer` を付けたときは、ファイルのパスやコミットの SHA のような内部の情報を省いて出力すること | 次 |

### 3.3 合意の記録

| ID | 要求 | フェーズ |
| --- | --- | --- |
| TRC-AGR-01 | 確認事項ごとに、質問・回答・回答者・回答日を一覧にすること | 初版 |
| TRC-AGR-02 | 仮定ごとに、内容・承認者・承認日を一覧にすること | 初版 |
| TRC-AGR-03 | 回答者や日付の欄が空のときは、レポートで警告すること | 初版 |
| TRC-AGR-04 | 回答や承認が trace.md に書き込まれたコミットと日時を、git の履歴から取り出して示すこと | 次 |

### 3.4 リリース単位の集約

| ID | 要求 | フェーズ |
| --- | --- | --- |
| TRC-REL-01 | `loomake trace report --release <タグ>` で、前のタグからそのタグまでに archive した change をまとめた検収レポートを出力すること | 次 |
| TRC-REL-02 | 要件書の版ごとに、要件の総数と、反映済・範囲外・確認待ちの数を集計すること | 次 |

## 4. 非機能要件

| ID | 種別 | 要求 |
| --- | --- | --- |
| TRC-N-01 | 依存 | 実行時の依存を `@loomake/core` と `@loomake/kit` だけにすること |
| TRC-N-02 | 環境 | ネットワークに接続しなくても動くこと |
| TRC-N-03 | 再現性 | 同じ入力と同じ証拠からは、毎回同じレポートを出力すること |
| TRC-N-04 | 性能 | 要件 500 件の change のレポートを 5 秒以内に出力すること（暫定） |
| TRC-N-05 | 配布 | HTML のレポートを 1 つのファイルで完結させ、外部の CSS やスクリプトを読み込まないこと |
| TRC-N-06 | 文書 | レポートを日本語で出力すること |
| TRC-N-07 | 環境 | Node.js 20.19 以上で動作すること |
