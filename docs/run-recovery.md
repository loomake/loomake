# runを中断したときの再開

`loomake run --change <change-id>`を再実行すると、既存のchangeブランチと未完了のタスクを使う。最初に`git status`と直前の`.loomake/runs/<run-id>/summary.json`を確認する。タスクとコミットの内容を読み、未コミットの変更を残すか、必要な部分を直すかを判断する。ログのために作業内容を削除する必要はない。

## 二重起動の防止

同じGit作業ツリーでrunを同時に起動すると、後の実行は終了コード1で止まる。dry-runも対象になる。通常終了、SIGINTによる中断、例外では、自分のロックを解放する。

ロックは`git rev-parse --absolute-git-dir`で確認できるディレクトリの`loomake-run.lock`に置く。PID、ホスト名、所有トークンを記録する。Git worktreeごとにロックを分ける。

同じホストで所有プロセスが終了済みと確認できれば、次のrunがロックを回復する。PIDが再利用されて生存中のプロセスを指している場合は回復しない。プロセスを調べる権限がない場合も、終了したとは判断しない。

## 自動回復できない場合

所有者の情報が壊れている場合、別ホストが所有する場合、回復用の`loomake-run.lock.recovery`が存在する場合は、自動で削除しない。

1. エラーに表示されたロックの場所と、そのPID・ホストを確認する。
2. 所有ホストで対応するrunとエンジンが終了していることを確認する。作業ツリーを共有している場合は、その利用状況も確認する。
3. 終了を確認できた場合だけ、表示された専用ロックファイルを取り除く。Gitの`index.lock`など、別のロックは削除しない。
4. 作業内容と直前の実行記録を確認し、同じchangeを再実行する。

ホスト名が同じ別PID名前空間から、同じ作業ツリーを共有する構成は対象外とする。別ホストのプロセスを確認できない状態では、ロックを手動削除しない。

## 記録と外部操作

同じchangeを同じ秒に再実行しても、記録のディレクトリは別に作る。最初は従来の日時形式を使い、名前が衝突したら連番を付ける。

ロックは同時実行を防ぐための仕組みであり、エンジンが残した変更を取り消す仕組みではない。PR作成などの外部操作が失敗した場合は、GitHubとローカルの状態も確認する。PR作成の再試行で重複を避ける仕組みは、引き続き改善対象としている。
