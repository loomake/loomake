# 実際の Claude Code での run の試用

2026-10-24 に、ビルドした CLI（ブランチ improve-oss-quality）で `loomake run` を実際の Claude Code に動かした記録。偽のエンジンを使う自動テストでは確かめられない、エンジンの指示の守り方・時間・費用を見るためのもの。

## 条件

- Claude Code 2.1.308、devcontainer（Linux、Node 24）
- 試用のプロジェクトは一時ディレクトリに作り、Vitest で JSON のレポートを書き出す。`loomake init` で導入し、commands は `npm test` だけ
- `run.timeoutMinutes` を 15、`run.maxFixes` を 2 にした
- git の remote は設定していない。そのため、どの試用も証拠のコミットのあとの push で止まり、PR は作っていない

## 結果

| 試用 | 確かめたこと | 結果 | エンジンの呼び出し | 時間 | 費用（USD） |
|---|---|---|---|---|---|
| 1 | tasks と仕様がそろった change（2 要件・3 Scenario） | 実装・完了ゲート・証拠の記録まで進んだ | 1 回 | 33 秒 | 0.25 |
| 2 | tasks に REQ-002 を書かない change。完了ゲートの不合格から直せるか | 最初の完了ゲートが「テストが無い要件：REQ-002」で不合格になり、1 回の直しで合格した | 2 回 | 175 秒 | 0.56 |
| 3 | 仕様が端数の扱いを決めていない change。推測せずに質問するか | 「切り捨て・四捨五入・切り上げのどれにしますか」と質問し、ファイルを変えずに止まった | 1 回 | 26 秒 | 0.21 |

3 件とも、エンジンは自分でコミットせず、tasks.md・trace.md・仕様を書き換えなかった。試用 1・2 のテストは、Scenario の値（`こんにちは、山田さん` と空の名前の Error）をそのまま確かめていた。

試用 2 の前に、別の試用から写したブランチ `loomake/add-greet` が残っていたため、run は既存のブランチを再開し、すべて完了済みとして終わった。再開の動作としては仕様どおりである。

## この記録が示さないこと

- 件数は 3 件で、小さい change だけを試した。大きい change や、既存のコードがあるプロジェクトでの完了率は分からない
- push・PR の作成と、GitHub との接続は試していない
- 費用はこの時点の Claude Code の出力（`total_cost_usd`）で、料金や使うモデルが変われば変わる
- `--skip-permissions` と、コンテナの外での実行は試していない
