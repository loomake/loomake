# 柱1の計測項目

[11月計画](../plan-2026-11.md)の柱1で、Loomakeを使うchangeと使わない比較用のchangeを、同じ5項目で記録するための定義です。[開発効率の記録様式](../effort/template.md)を写し、1対象につき `docs/effort/<対象>.md` へ記録します。今回の変更には実測値を含めません。

## 状態と欠測

各項目の状態は次の4つから選びます。未取得や対象外を0へ置き換えません。

| 状態 | 値 | 必須の補足 |
|---|---|---|
| 記録あり | 取得した値。0も記録できる | 単位・取得元・観測期間 |
| 不明 | 空欄 | 取得できなかった理由 |
| 非該当 | 空欄 | 適用しない理由 |
| 観測中 | 空欄 | 観測を終える日 |

0を書けるのは記録ありのときだけです。観測期間が終わっていない手戻りの数は観測中にし、0と確定しません。過去の記録を補うときも、出典がなければ不明にします。

| M1 | 実装前に見つかった確認事項の数 | 実装前に記録した要件の問いの数。キーは(change, Q-ID)。回答済み・非ブロッキングも含め、同じQ-IDは1件とし、ブロッキング件数を内訳に書く。実装後に増えた問いは別記する | 件 | 仕様ゲートの初回成功後、最初の実装コミットの親にあるtrace.md | `git show <親>:openspec/changes/<id>/trace.md` の確認事項の表 | 記録の柱1の節と確認事項の表 | 基準時点の表がなければ不明 | 同じ問いの表を記録に置き、実装着手時刻より前の行を数える。表がなければ不明 |

## 取得元の注意

- M1は発見した問いの総数です。`pending-approvals.mjs` の現在の未回答件数では代用しません。
- M2は停止事象の数で、実行回数ではありません。停止の日時・SHA・失敗項目・区分をその都度記録します。
- `delivery-metrics.sh` の `merged_hours` はPR作成からマージまでの時間です。要件書を読み始めてからのM4には代用しません。
- `ask-opus` の `costUsd` はその実行の分だけです。ほかのツールや端末の費用まで取得したとは扱いません。
- `metrics-tokens.py` はLoomakeのログを日単位で集計し、changeを分けず、外のリポジトリも含めません。M5の取得元にはせず、日次トークン数からchangeの費用を推定しません。この記録のために私的ログを読み取りません。

## 比較の組み方

柱1の節に、比較の組（2記録を結ぶID）・Loomakeの利用（あり／なし）・規模（要件の数と要件書の範囲）を書きます。比較する記録は同じ計測定義と観測期間を使います。

既存の比較方式（AIなしの人力／人がAIを操作する方式）と比較の種類（推定との比較・人力実測なし／人力実測あり）は残します。LoomakeなしでAIを使っても、人力実測ありにはしません。実測した人力の記録がない限り、推定との差と書きます。事前の推定の最小・最大・根拠は書き換えません。

## FR-50との対応

| 柱1の項目 | FR-50・7.8の欄 | 対応と区別 |
|---|---|---|
| M4(a) 人の実作業時間 | Loomake利用時の人の実績 | 既存の5区分を合計する。判断根拠を探す時間は内数のまま |
| M5 AIコスト | 費用 | 区分と取得範囲を残して要約し、詳しくは柱1の節に記録する |
| M1 確認事項の数 | 判断要求とは別の項目 | M1は実装前に記録した問いの数。判断要求は人に判断を求めた回数 |
| M2 仕様ゲートの停止 | 試行とは別の項目 | M2は重複を除いたspec-onlyの停止。runnerやAIの試行回数ではない |

`--effort` と効率の表へ列を足すかどうかは [Issue #68](https://github.com/loomake/loomake/issues/68)で決めます。この文書はCLI・Evidence・公開schemaや要件定義のFR-50・7.8を変更しません。dashboardと `metrics-data` の作業は保留中の [Issue #273](https://github.com/loomake/loomake/issues/273)のままです。

## 記録を始める条件

定義文書と様式が通常L3の検証・レビューを経てmainへ採用されたら、11月7日以降に始めたchangeから使います。過去分を追記できるのは取得元がある場合だけで、出典がない値は不明にします。実案件の準備と実測は今回の変更に含めません。

公開する記録は匿名化した対象名と集計値に限り、セッション本文や自由なログを含めません。外の案件の匿名化資料は利用者が用意します。
