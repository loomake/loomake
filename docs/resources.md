# 入力と実行の資源予算

Loomakeは、文書・JSON・探索の読み取りとエンジンへの指示に上限を設ける。これらは入力処理の予算であり、プロセス全体のメモリやディスクをOSで隔離する設定ではない。

## 入力の上限

| 対象 | 1ファイル | 同じ読み取り処理の合計 |
|---|---:|---:|
| 設定、仕様・trace・tasks、AGENTS.md、proposalなどの文書 | 1MiB | 16MiB |
| テストのJSONレポートと証拠JSON | 64MiB | 128MiB |

上限はUTF-8のバイト数で数え、ちょうどの量は受け付ける。設定の読み取り、verifyの文書の読み取り、証拠スナップショットの読み取りなど、各処理でreaderを共有して合計を確認する。設定・文書・JSONのすべてを、run全体で16MiBに収めるという意味ではない。trace reportは同じchangeの証拠を逐次検証し、合計128MiBまでに制限する。

指示に読む文書とは別に、組み立てたエンジン指示全体も16MiBまでとする。対象タスク、見出し、検証失敗の情報などを含めて数え、上限を超えた指示をエンジンへ渡さない。

生成する証拠も、整形と末尾改行を含めたJSONを64MiBまでに制限する。保存前に実際のJSONを形式検証へ通し、JSONの読み取り上限を超える証拠を作らない。不合格の検証結果を保存する動作は維持する。ここでの検証は証拠JSONの形式であり、検収表を作るには保存した文書も解析できる必要がある。保存の失敗は[run-recovery.md](run-recovery.md)を参照する。

ファイルは読み取り前のサイズを確認し、開いた対象も通常のファイルか確かめる。読み取り中に伸びた場合も、実際の量で止める。超過検出には最大1バイトの追加読み取りを使い、超えた内容は返さない。成功・失敗ともファイルを閉じる。

## 探索とリンク

ディレクトリは4096項目、探索の深さは32までとする。探索を始めるディレクトリを深さ0とし、ディレクトリへ進むごとに1増やす。全件を読み込む前に、逐次列挙して訪問数を確認する。verifyの隠し項目とnode_modulesの除外は維持するが、除外名も訪問数には数える。

探索で見つかったリンクと、最終要素がリンクの入力ファイルは拒否する。通常のファイル・ディレクトリ以外も受け付けない。除外した名前のリンクをたどることはない。プロジェクトのルート自体がリンクを通る既存の使い方は維持する。

この確認は、設定されたパスの全祖先や、OSをまたぐ同時差し替えを隔離する仕組みではない。信頼した作業ツリーと、必要な実行環境の制御を前提にする。

## 止まったとき

制限を超えると、対象と上限を含むUsageErrorを返す。開始前のCLIは使い方の誤りとして終了コード2、開始後のrunは状態を保って終了コード1で止まり、理由を記録する。エンジンやPR作成へ進む前に止める。

表示されたファイル・合計・探索範囲を確認し、どの文書やchangeを1回で検証するか見直す。循環するリンクは通常のファイル配置へ直す。証拠は上書きしない。CLIの設定には、これらの上限を緩める項目はない。

この変更から、それまで読めた過大な入力やリンクを使うspecsでも止まる場合がある。入力制限の変更としてchangesetはminorを指定する。JSONの出力形式とschemaVersionは変更しない。

## 測定の範囲

[benchmark.mjs](../openspec/changes/bound-input-resources/benchmark.mjs)は、リポジトリのルートから次で実行する。保存先は新しいファイル名にする。

```sh
pnpm build
node openspec/changes/bound-input-resources/benchmark.mjs .loomake/quality/input-benchmark.json
```

小規模・中規模・上限ちょうど、ファイル・合計・深さ・項目数・証拠JSON・指示全体の超過を、別々のプロセスで測る。事前に置く測定上の予算は、通常の入力処理が1秒・ピークRSS256MiB、証拠JSONの合計超過が3秒・512MiBである。これらはこの測定の目安で、製品がRSSを強制する設定ではない。

時間は入力処理の開始から受理・拒否までとする。ピークRSSはモジュールの読み込みとfixture作成も含むプロセス全体の値である。ファイル作成後の読み取りなので、キャッシュのあるこのホストでの結果として扱う。bytesは対象ファイルの内容量で、指示の試験では別に16MiBの失敗情報を加える。

結果とソースのハッシュは[results.json](../openspec/changes/bound-input-resources/results.json)に記録する。この測定はCLI全体、ネットワークファイルシステム、別OS、顧客の全規模での性能を示すものではない。

## 別に管理する資源

エンジンのstdoutとstderrは既定64MiBまでで、run.maxOutputBytesで指定する。runには時間の上限もある。一方、エンジンが直接書くファイル、実行記録の累積ディスク容量、Gitとghを含むすべての外部操作の期限、initなど対象外の入力経路は、引き続き改善対象である。

現在の保護範囲は[security.md](security.md)、中断と再試行は[run-recovery.md](run-recovery.md)、最新の評価と残る項目は[review.md](review.md)を参照する。
