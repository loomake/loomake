# ci-test-diagnostics Specification

## Purpose

このリポジトリの CI で、テストの失敗と所要時間を実行環境に結び付けて保存する。開発者がログを毎回読み直す負担を減らし、失敗の調査と実行間の比較に使う情報を提供する。

## Requirements

### Requirement: 実行を識別できるテスト結果の保存

キャンセルされておらず、文書だけと判定されず、checkout と Node の準備が済んだ quality ジョブは、run の URL・ID・試行番号、checkout の SHA、OS、Node の版、シャード、テストステップの結果を診断情報に記録する SHALL。JSON レポートがあればその写しも保存する SHALL。同じ run の別 OS・シャード・試行の保存先は分ける MUST。

Source: REQ-289

#### Scenario: 同じ run の複数の実行
- **WHEN** Windows の 1/2 と 2/2 のシャード、および同じ run の再試行が動く
- **THEN** それぞれの診断情報が異なる名前で保存され、元の実行を識別できる

#### Scenario: checkout したコミットの記録
- **WHEN** PR のマージ結果を checkout してテストする
- **THEN** 診断情報は実際に checkout した SHA を示し、PR の head SHA と取り違えない

### Requirement: 結果と所要時間の要約

診断はテストの状態別件数、失敗したテストのファイルと完全名、所要時間の上位を日本語のジョブ要約へ出す SHALL。JSON レポートの欠損・不正・テスト未実行を明示し、成功と扱わない MUST。表示件数と文字数には上限を設け、省略を明示する SHALL。テスト名などに含まれる Markdown を表示用にエスケープする MUST。

Source: REQ-290

#### Scenario: 失敗と遅いテスト
- **WHEN** 成功・失敗・skip と所要時間を持つ JSON レポートがある
- **THEN** 状態別件数と失敗の一覧、所要時間順の一覧を出し、skip を成功に含めない

#### Scenario: レポートが使えない
- **WHEN** レポートがない、不正な JSON である、またはテスト結果が空である
- **THEN** その状態を示し、テスト全件成功とは表示しない

#### Scenario: 大きな結果と表示用の文字
- **WHEN** 表示の上限を超える結果や Markdown の記号を含むテスト名がある
- **THEN** 表示を上限内に収め、省略の有無を示し、テスト名を文章として表示する

### Requirement: 品質判定を維持する診断の実行

キャンセルされていない実行では、診断の生成と保存をテストが失敗した場合にも実行する SHALL。元の品質コマンドの失敗を成功へ変えず、品質を検査するテストの skip・期待値・期限・再試行・実行条件は変更しない MUST。ただし、CI 構成の既存試験の期待値は、本会話の明示承認に基づき、既存8条件を維持して診断2条件を追加する更新に限って認める。保存対象は診断情報・要約・JSON レポートの写しに限定し、保存期間を7日にする SHALL。文書だけと判定して品質コマンドを飛ばすジョブでは診断を生成しない MUST。

Source: REQ-291

#### Scenario: 失敗後に保存する
- **WHEN** テストが失敗して後続のビルドへ進まない
- **THEN** 診断を生成して保存し、ジョブは失敗のままになる

#### Scenario: 診断の生成に失敗する
- **WHEN** テストの失敗後に診断の生成も失敗する
- **THEN** 元の失敗を維持し、生成済みの保存対象があれば保存処理を試みる

#### Scenario: 文書だけの PR
- **WHEN** 既存の文書判定によって quality の品質コマンドを飛ばす
- **THEN** 診断を生成せず、gate の実行条件は変わらない
