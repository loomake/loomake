# run-decision-policy Specification

## Purpose
loomake run が、エンジンの終わり方と完了ゲートの結果から、続けるか止まるかを決める規則を、ファイルや外部コマンドを使わない純粋な判断として定める。判断の優先順位と回数の境界を、直接の試験で確かめられるようにする。

## Requirements

### Requirement: エンジン終了後の純粋な判断
runnerは、観測済みのエンジン終了結果とHEAD・ブランチ・Git内部の変更理由から、続行または停止を返す純粋関数を持つ SHALL。中断、出力上限、時間上限、質問、非ゼロまたは不明な終了コードの順に判定する SHALL。変更理由がある場合はHEAD・ブランチの変更をGit内部の変更より優先し、終了の理由より先に書き、中断の状態を保持する SHALL。正常な終了だけなら続行する SHALL。公開されるrunの挙動は維持する SHALL。

Source: REQ-204

#### Scenario: 複数の停止条件
- **WHEN** 中断・上限・質問・終了コードが重なる
- **THEN** 定めた優先順位で停止し、中断はinterruptedとなる

#### Scenario: Git変更とエンジン終了
- **WHEN** HEADの変更、Git内部の変更、エンジン終了が重なる
- **THEN** HEADの変更理由が先になり、中断の状態と追加の終了理由を保持する

#### Scenario: 正常な終了
- **WHEN** 変更も質問も制限超過もなく終了コード0で終わる
- **THEN** 続行を選ぶ

### Requirement: 完了ゲート後の純粋な判断
runnerは、観測済みの作業状態の変更、検証の合否、中断、期限超過、実施済みの修正回数と上限から、合格・再修正・停止を返す純粋関数を持つ SHALL。作業状態が変わったら最初に止まり、変わらず合格なら次へ進む SHALL。不合格で中断があればinterruptedの状態で止まり、期限超過なら停止し、それ以外でも修正回数が上限以上なら停止し、未満なら再修正する SHALL。合格した場合は、修正回数や期限超過の記録より合格を優先する SHALL。

Source: REQ-205

#### Scenario: 合格と状態変更
- **WHEN** 検証は合格だがHEADかブランチが変わる
- **THEN** 停止を選ぶ

#### Scenario: 修正回数と期限
- **WHEN** 検証が不合格で修正回数が上限の直前・一致・超過となる
- **THEN** 直前だけ再修正し、一致と超過は停止する。期限超過があれば回数より優先して停止する

#### Scenario: 合格の優先
- **WHEN** 作業状態が変わらず合格している
- **THEN** 修正回数の上限や期限超過の記録があっても合格を選ぶ

#### Scenario: 品質コマンドの中断
- **WHEN** 作業状態が変わらず完了ゲートが不合格で、品質コマンドが中断された
- **THEN** 再修正のエンジンを呼ばずinterruptedで止まる。検証中の状態変更と合格の優先順位は維持する

### Requirement: 判断の副作用と誤りの直接検査
判断する関数は入力を変更せず、ファイル・Git・エンジン・時計・環境変数を読まず、渡された値だけを使う SHALL。直接試験は主要な優先順位と境界を含み、意図的に逆転した規則をassertion失敗として検出する SHALL。副作用の順序と作業状態の保持は既存の統合試験でも検査する SHALL。

Source: REQ-206

#### Scenario: 同じ観測値
- **WHEN** freezeした同じ観測値で繰り返し判断する
- **THEN** 入力を変えず、同じ結果を返す

#### Scenario: 優先順位の逆転
- **WHEN** コピーで中断と上限の優先順位、状態変更と合格の優先順位、修正回数の境界を変える
- **THEN** 元の試験は成功し、各変更は同じ試験のassertionで失敗する

### Requirement: エンジンの変更の有無の純粋な判断
runnerは、段階（タスクか完了ゲートの直しか）、エンジンの変更が index にあるか、エンジンの本文の観測値から、コミット・変更なしの完了・停止を返す純粋関数を持つ SHALL。変更があればコミットを選ぶ SHALL。変更がなく直しの段階なら停止を選ぶ SHALL。変更がなくタスクの段階なら、行頭の `LOOMAKE-NOCHANGE:` に続く空でない理由の最初の 1 つがあれば、その理由とともに変更なしの完了を選び、なければ停止を選ぶ SHALL。関数は入力を変えず、ファイル・Git・エンジン・時計・環境変数を読まない SHALL。直接試験は、直しの段階の停止と行頭の判定を意図的に変えたコピーを、assertion 失敗として検出する SHALL。

Source: REQ-332

#### Scenario: 変更がある
- **WHEN** タスクか直しの段階で、変更があり、本文に合図がある
- **THEN** コミットを選ぶ

#### Scenario: タスクの段階で変更がない
- **WHEN** 変更がなく、本文に行頭の合図と理由がある、行頭でない合図だけがある、理由のない合図だけがある、合図がない
- **THEN** 最初の場合だけ理由とともに変更なしの完了を選び、ほかは停止を選ぶ

#### Scenario: 直しの段階で変更がない
- **WHEN** 変更がなく、本文に行頭の合図と理由がある
- **THEN** 停止を選ぶ

#### Scenario: 判断の逆転
- **WHEN** コピーで、直しの段階の停止を合図で迂回させるか、合図の行頭の条件を外す
- **THEN** 元の試験は成功し、各変更は同じ試験の assertion で失敗する
