# Design

## Context

coreはMarkdownの列名をキーにしたDTOを返す。verifyは同じ処理でI/Oとルールの判定を行う。既存の型とJSON契約は変更せず、追加APIと内部の利用で分離する。

## Goals / Non-Goals

モデルと判定を直接検査できるようにする。クラス階層、Repository、イベント基盤は追加しない。全モデルを一度に作り替えない。

## Decisions

- RequirementIdは検証済みの文字列を表す型とする。要件の状態は既存の4値のunionとする。DTOからモデルへの変換はParseResultでエラーと行を返す。
- 質問のブロッキング値は既存どおりyesを大文字小文字を区別せず真とする。回答と承認は既存どおり空文字を未決とする。
- 判定関数はreadonlyのモデルを受け取り、該当するIDを返す。日本語の表示文とI/Oはkitが担当する。
- テストとの対応はファイル名の正規化をkitで済ませてからcoreに渡す。coreは対応と不足を決定する。
- 主要ルールの反転を検出できるテストを用意し、後続のmutation検査で利用する。

## Risks / Trade-offs

不正なIDの台帳は新たに不合格になる。REQと3桁以上の数字という既存のID形式に揃えるための変更で、パーサ自体の戻り値は維持する。
