# TDD実行記録

## 1.1 AIシナリオ試験

シナリオのスクリプトがない現行実装で統合テストが失敗した。配布物を3つの独立したプロジェクトへ導入し、初回導入と再実行、既存ファイルの保護と通常操作、原因修正からの復旧を実行するスクリプトを追加した。統合テストは成功した。

操作ごとにコマンド・期待した終了コード・実際の終了コード・出力・所要時間をjourneys.jsonへ記録する。4回の意図した失敗を含め、期待した結果と実際の結果が一致したことを検証する。

## 試験の実行方法

開発環境で`node scripts/ai-journeys.mjs <新規ディレクトリ>`を実行する。5パッケージをpackし、オフライン導入した配布物だけでCLI操作を試す。記録は指定したディレクトリのjourneys.jsonへ出力する。既存のディレクトリは上書きしない。

## 評価の限界

AIが作成して実行する再現可能なシナリオで、人による利用者試験や独立した3人分の試験ではない。サンプルchangeとレポートのfixtureを使い、顧客のアプリケーションの機能を実装・検証する試験ではない。実エンジンとGitHubには接続しない。doctorの診断範囲や導入時の手作業の十分さは別にレビューする。

## ワークスペース内での再検証

結果をワークスペースへ保持する再実行で、コピーしたfixtureのファイルをGitが読めない失敗が出た。成功扱いにせず、fixtureを明示的な読み書きで複製する処理へ変更した。同じ保存先で再実行すると、初回11操作、通常15操作、復旧16操作の42操作が成功した。4操作の意図した終了コード1も一致した。ワークスペース内と一時ディレクトリの両方を回帰テストへ追加し、配布物の検査と合わせて3件が成功した。
