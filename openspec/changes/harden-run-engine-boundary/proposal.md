# harden-run-engine-boundary

## Why
不正な直し方の検出（REQ-109〜REQ-111）は、エンジンが終えたあとの作業ツリーと HEAD の差分を見る。そのため、`--skip-permissions` などでエンジンが自分で `git commit` すると、コミットした変更は検出の対象から外れる。ブランチを切り替えた場合も、run は切り替え先のブランチでタスクを完了にしてコミットしてしまう。docs/evaluation.md の「技術面」の気になる点 2 で指摘された。

## What Changes
- エンジンを呼ぶ直前の HEAD のコミットとブランチ名を覚え、エンジンが終わったあとに比べる。変わっていれば、タスクを完了にせず、コミットもせずに止まる（REQ-126）
- 止まるときは、呼ぶ前と後の SHA とブランチ名、その間の差分を表示し、確認と元に戻す手順を案内する（REQ-126）
- エンジンが失敗・質問・時間切れ・中断で終えたときも、同じように比べる（REQ-126）

## Non-goals
- エンジンのコミットを run が取り消すこと、ブランチを戻すこと。run は検出して止まるだけで、戻すかどうかは人が決める
- エンジンのコミットを受け入れたうえで、その差分を不正な直し方の検出にかけること
- エンジンを動かしているあいだの git の操作を封じること
- HEAD とブランチ名のほかの変化（ほかのブランチやタグの書き換え、stash）の検出
- docs/usage.md と README.md の run の説明の更新（いま利用者が編集中のため、別に行う）

## Impact
- 影響する capability：run-guards（Requirement の追加）
- 影響するコード：`packages/runner/src/run.ts`・`guards.ts`・`git.ts`、`packages/runner/test/`
