# セキュリティ再レビュー後の仕様更新案

状態：提案。製品の振る舞いと既存仕様は変更していない。

## 確認した事実

Linux ARM64の一時リポジトリで、次の3件を再現した。実際のClaude・GitHub・本番リポジトリの被害を確認したものではない。

1. エンジンが正常終了しても、標準出力を共有しない同じプロセスグループの子が生存した。runClaudeが戻った時点ではなかったファイルを、その子が後から作成した。
2. hooks内の通常ファイルを検査すると戻ったが、同じ場所のFIFOでは戻らず、外側の試験が1500msで強制停止した。製品自身の期限で停止した結果ではない。
3. 既存のpre-commitのリンク文字列を保ってリンク先の実行ファイルを変えると、Git内部のダイジェストと変更ガードは変化を検出せず、その後の一時コミットで変更後のフックが実行された。REQ-204はリンク先をたどらないと明記しており、この結果は現行仕様の違反ではない。

## 推奨する変更範囲

新しいchangeで、エンジンの正常終了後にも同じプロセスグループの残存する子を停止し、後処理を待ってから戻る仕様と試験を追加する。既存の時間切れ・中断・出力上限・終了コード・出力の扱いは維持する。Windowsの停止手段と保証できる範囲は設計で確認し、未検証の成功を記録しない。

Git内部のスナップショットは、特殊ファイルを開く前に検出し、日本語で対象と理由を示してコミット前に止める。通常のフック、リンク先のないリンク、ディレクトリへのリンクの現行契約は維持する。既存のリンク先をたどる変更は今回含めず、リンク先やそこから呼ぶコードまで保護する仕組みではないことを文書に明記する。

正常終了後の子の停止と特殊ファイルの扱いは、現行仕様の明記範囲を広げる。AGENTS.mdの「仕様に書かれていない振る舞いは実装しない。必要だと気づいたら、実装を止めて change の specs を更新する提案をする。」に従い、先にこの変更範囲を確認する。
