# TDD実行記録

## 判断の直接試験

正常終了と再修正だけを返す仮実装に対し、直接試験24件中20件がassertionで失敗した。停止条件の優先順位と修正回数の境界を実装し、既存のrun・Git保護を含む関連122件が成功した。別作業と要件IDが重複したため、この変更のIDをREQ-204〜REQ-206へ採番し直し、期待値は維持した。採番後の直接試験と変異を入れた試験25件も成功した。

## コピーでの対照

同じ24件の直接試験を変更のないコピーで成功させてから、中断と出力上限の優先順位、作業状態の変更と合格の優先順位、修正回数の一致の3条件をそれぞれ変えた。3条件すべてで同じ試験のassertionが失敗した。既存のclassifyMutationでテスト名の過不足、実行エラーと未実行を確認し、元のソースとテストが変わっていないこともassertする。

## 保護する契約

公開API、設定、JSON Schema、理由の文面と終了コードを維持する。エンジン、Git、時計、ファイルを読む処理は呼び出し側に残す。判定結果は実行固有の内部モデルとし、coreの実行時依存ゼロとパッケージの依存方向を維持する。
