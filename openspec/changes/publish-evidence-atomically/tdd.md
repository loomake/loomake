# TDD実行記録

## 1.1 証拠の形式とサイズ

シリアライズの単体テストを先に追加し、未実装のモジュールで失敗を確認した。実際のrunRecordでも、64MiBを超える結果と不正なschemaVersionを保存してしまう2件の失敗を確認した。通常の生成結果をreportで読めるケースも維持した。

JSONの形式と末尾改行を含むUTF-8のサイズを保存前に検証した。さらにtoJSONで変換後の形が変わる1件を追加し、失敗を確認した後、完成したJSON自体も読み取り側の形式検証へ通した。スキーマ定数を分けて循環参照を避け、既存のexportは維持した。

## 1.2 公開と保存失敗の再開

原子的な公開の単体9件を先に追加し、未実装モジュールで失敗を確認した。runの保存先作成をEACCESにする統合試験も先に追加し、停止記録ではなく例外になる失敗を確認した。

完全に書いて同期・閉じた一時ファイルを、linkで上書きせず公開する処理を追加した。部分書き込み、同期失敗、linkの失敗、既存名、自分が作れない一時名、公開後の片付け失敗を確認した。I/OエラーをUsageErrorへ変換し、runは保存失敗後の停止記録と実装コミットを保つ。

公開後の片付け失敗についても、完全なJSONの確認、一時名の削除、証拠の手動コミット、再検証と同じ証拠の再利用から完了する経路を追加した。実装・証拠・PRを重複させないことを確認した。JSON文字列を返さない変換の1件も失敗から修正し、変換できない値はUsageErrorで止める。関連242件、型検査とlintが成功した。既存の期待値と品質設定は変更していない。

## 2.1 復旧手順と範囲

保存前の形式・64MiB上限、保存先に必要なハードリンク、通常の保存失敗と公開後の片付け失敗、強制終了後の確認手順を文書へ記載した。JSONの形式と検収表の文書解析を区別し、不合格結果の保存と既存の版・ファイル名を維持する。保存先の互換性への影響をminor changesetへ記録した。

公開後の片付け失敗の試験では、JSONの内容だけでなくtrace reportの成功も確認してから、一時名の削除と証拠のコミット、再試行まで実行した。復旧2件が成功した。関連242件と型・lintの成功を確認した。

## 強制終了時の実プロセス確認

最初の完了ゲートは全501件で成功した。その後、文書化した強制終了後の手順も確認するため、書き込み途中・公開直前・公開直後の3件を追加した。実際のwriterソースの型だけを除去して別プロセスで実行し、ネイティブ操作の境界で待機させてSIGKILLした。

書き込み途中と公開直前は最終名がなく、公開直後は完全な最終JSONが残った。所有者のcloseを待った後、自分の一時名だけを片付け、再実行で最終JSONが1つだけになることを全3件で確認した。別OSや電源断の試験ではない。
