# Proposal

## Why

PR #118 の Windows 診断では、配布物操作が約67秒、push・create の期限試験が各約47秒だった。期限試験には40秒の共有予算を使う検証があり、総時間だけでは削れる処理を判断できないため、準備・通常処理・停止待ち・再実行・後片付けを分けて観測する。

## What Changes

- 明示的に計測を有効にした実行だけ、対象試験の区間と経過時間を保存する。
- 配布物操作の既存のコマンド別時間を利用し、共有の build・pack は個別テストの時間と分ける。
- Windowsで同じ対象を3つの独立した実行として測り、各実行の条件と結果を保存する。

## Capabilities

### New Capabilities

- `ci-phase-profiling`: 遅い試験の区間ごとの時間を収集し、実行条件とともに比較可能な形で保存する。

### Modified Capabilities

なし。既存の検証の期待値・skip・期限・再試行・品質CIの実行条件は変更しない。

## Impact

対象は計測用スクリプトと試験、配布物操作・期限試験・共有準備の計測箇所、独立したWindows計測workflowと説明文書。製品runtimeや既存ci.ymlは変更しない。PR #118を土台とする別ブランチで進め、既存の診断artifactの3ファイル契約は維持する。
