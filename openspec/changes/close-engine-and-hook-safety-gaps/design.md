# Design

## Context

動機と承認された範囲はproposal.md、受け入れ条件は差分仕様とtrace.mdに示す。現在の`runClaude`はPOSIXでエンジンを独立したプロセスグループにし、時間切れ・中断・出力上限でだけ停止処理を呼ぶ。`close`では進行中の停止処理を待つが、親が普通に終了し、標準出力を共有しない子が残る場合は停止処理がない。

Git内部の比較は`filesUnder`でディレクトリをたどり、`entryDigest`でリンク文字列かファイル内容を読む。リンク以外の種類を通常ファイルと同じように読むため、FIFOの読み込みが待ち続ける。REQ-204ではhooks内のリンク先をたどらないことが既に決まっている。

## Goals / Non-Goals

**Goals:** エンジンを呼んだ後の変更検査とコミットへ進む前に、同じPOSIXプロセスグループの残存する子の停止を待つ。フックの特殊ファイルを内容の読み込み前に拒否する。既存の結果型・停止理由・通常フック・リンク文字列の契約を保つ。

**Non-Goals:** WindowsのJob Object導入、別セッションへ離脱した子の追跡、OSの隔離、フックのリンク先のダイジェスト化、フックの一律無効化、他プロセスによる同時書き換えへの完全な対策は含めない。新しい設定や実行時依存は足さない。

## Decisions

### 親の終了を契機に同じグループの後処理を始める

POSIXでは、エンジンの`exit`で同じグループの後処理を始める。通常終了でも`close`まで待ってから停止すると、子が出力のパイプを保持している場合に停止を始められないためである。時間切れ・中断・出力上限の停止と、通常終了後の後処理は同じ停止用Promiseを共有し、複数回の停止や待機を増やさない。`close`でそのPromiseを待ってから出力を確定して返す。

終了した親のコードと出力は保持する。通常終了後の後処理を、時間切れや中断の発生として扱わない。ローカルのタイマーと中断監視の終了時点を整理し、親の終了後に後処理を待つことだけで誤ったフラグが立たないようにする。run全体の残り時間の検査は既存のまま保つ。

同じグループへのSIGTERMと、既存の250msの猶予後のSIGKILLを再利用する。グループが既に存在しない場合は後処理済みとして扱う。SIGKILLを送っただけでは子がまだ終了処理の途中で見えるので、送ったあとは同じグループのメンバーが動作していなくなるまで待ってから戻る。自分の子はexitで回収する。孫はゾンビ（親が回収していないだけで利用者のコードを実行できない）と消滅を「動作していない」とみなし、initが回収しない環境でも待ち続けない。Linuxは/procを読み、ほかのPOSIXはpsのstatの先頭文字で判定する。どちらも読めなければグループへのシグナル0の存否だけを見る。カーネル内で待ち続ける子でrun全体を止めないよう、この待機は1000msを上限とし、超えたら従来どおりそのまま戻る。グループの確認に使うpsのtimeoutにも後処理の残り時間を渡し、期限が過ぎたあとは新しい確認を始めず、期限後に届いた確認結果も採用しない（psが止まっても待機全体が上限を超えない）。上限は差分仕様のScenarioにも記載し、実装の既定値（`GROUP_EXIT_TIMEOUT_MS`）と同じ値を保つ。グループが存在しない呼び出しにも猶予の待機を追加する場合は、回帰の所要時間を記録し、テストや製品の上限設定を緩めて通さない。

Windowsでは現在の明示停止時の`taskkill /T /F`を維持する。終了済みの親PIDにtaskkillを使うだけで子の停止を保証できるとは扱わず、この変更では通常終了後の子の停止を新しく保証しない。Linuxの結果はWindowsの実行証拠にしない。

### フックの種類を内容より先に判定する

`entryDigest`の`lstat`で、リンクは従来どおり`readlink`の文字列を使い、通常ファイルだけを内容の読み込みへ進める。それ以外の項目は、パスと特殊ファイルを読み込まない理由を含む日本語の`UsageError`で拒否する。ディレクトリの列挙は従来どおりで、配下の特殊ファイルも同じ判定を通す。

既存のrunの例外処理で、実行記録を作ったあとの検査エラーを終了コード1として記録する。エンジンを呼ぶ前のスナップショットで見つかった場合も、エンジンを呼ばず、タスクを完了にせず、コミット前に止める。検出したファイルや作業変更を削除しない。タイムアウト付きで特殊ファイルを読む案は採らず、内容を開く前に拒否する。

これは検査時点の種類を判定する対策であり、敵対的な別プロセスによる判定直後の差し替えを含めて、OSの隔離を提供する設計ではない。リンク先のコードを追跡しない決定も変えない。

### 実際のプロセスと特殊ファイルを使って回帰を確認する

新しい回帰にはREQ-212・REQ-208を付け、修正前のRedを保存する。子は起動完了と終了要求の無視の準備が済んだことを親へ知らせてから、親を終了させる。PIDが戻り時点で動作していないことと、予定された遅延書き込みが起きないことを両方確かめる。例外や試験失敗でも作成した子を回収する。試験用のPIDの状態判定は、Linuxでは/procで終了途中も区別し、ほかのPOSIXではpsのstatでゾンビと消滅を区別する。手元はLinuxだけなので、psの経路はLinuxでprocess.platformを差し替えて確かめ、macOSでの実行結果はCIに頼る。

FIFOの試験は別プロセスで実行し、試験用の外側の期限でプロセスを回収できるようにする。Redで外側から止めた事実を製品自身の停止成功とは記録しない。通常のフック、壊れたリンク、ディレクトリへのリンクが引き続き動く対照も確かめる。特殊ファイルを作成できないOSについて、実行していない試験を成功扱いにしない。

REQ-209は`docs/security.md`へ反映し、リンク先のコード・権限・POSIXグループ・Windowsの説明を確認する文書のテストを追加する。実際のClaudeやGitHubを使わない試験は、その範囲を記録する。

## Risks / Trade-offs

- 残存する子の停止に猶予分の時間が必要になる。既存の期限と全体回帰で影響を確かめ、上限設定を緩めない。
- POSIXの子が自分で別セッションに移った場合は同じグループへの停止で追跡できない。文書に範囲を明記し、信頼したリポジトリと隔離環境での実行を案内する。
- フックのリンク文字列が同じでもリンク先の内容は変わり得る。REQ-204を保ち、リンク先のコードの保護を約束しない。
- Linux以外の実行証拠は別途必要である。Windowsの通常終了後の子を停止したとは記録せず、既存の明示停止処理も実OSでの確認と区別する。

## Migration Plan

新しいchangeの仕様ゲート成功後、Redを確認してから実装する。runnerの修正にchangesetを付け、通常設定の完了ゲートとNode22.12での回帰を実行する。設定の移行は不要である。取り消す場合は修正をrevertし、子の残存と特殊ファイルの既知の問題が戻ることを評価記録へ明記する。
