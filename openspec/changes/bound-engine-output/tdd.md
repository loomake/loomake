# TDD実行記録

## 1.1 出力の制限

現行実装で出力予算の4件が失敗した。stdoutとstderrの合計を制限し、超過時に子を含めて停止する実装を加えた。新規4件と既存の停止3件の計7件が成功した。UTF-8の途中で切れる文字を保持せず、通常の失敗と上限ちょうどの出力は従来どおり扱う。

## 1.2 設定と停止結果

現行実装で統合テスト5件が失敗した。run設定の検証とエンジンへの上限の受け渡し、停止理由を追加した後、runner58件と出力予算4件の計62件が成功した。上限超過では未完了のタスクと途中の変更を残し、コミットとPRを作成しない。

## 出力予算

run.maxOutputBytesを省略すると64MiBを使う。正の安全な整数を指定できる。stdoutとstderrの合計を数え、上限超過を検出したら収集と転送を止め、エンジンと同じプロセスグループの子を停止する。UTF-8の途中の文字は保持しない。上限超過で保存するraw出力は途中までの内容になるため、元のJSON全体を復元できるとは限らない。

上限はエンジンから受け取る出力の予算であり、エンジンが直接書くファイルの容量や、run全体の累積ディスク使用量は保証しない。後者は外部の実行環境の制限と、後続のログ予算の設計で扱う。
