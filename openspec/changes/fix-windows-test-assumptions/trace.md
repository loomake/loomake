## 範囲

Issue #5 の調査結果のコメントにある原因のうち、①（CRLF）・②（フック）・③（配布物の準備）・⑤（待ち時間）の REQ-158 を扱う。④（偽の CLI）は change B、⑥（監視役の強制終了）は change C で扱う。

①の理由は、`\n` を直接書いた正規表現（release-security.test.ts の 32・43・77 行目）が CRLF に合わないことだけとする。調査結果のコメントにあった「36 行目の否定の検査が CRLF で中身に関係なく通る」は誤りで、レビューで訂正された。JavaScript の `m` フラグの `$` は `\r` の前でも一致するので、36 行目の検査は CRLF でも働いている。

レビューは修正の着手を認めたもので、実装やマージの承認ではない。
