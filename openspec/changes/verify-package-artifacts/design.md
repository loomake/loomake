# Design

## Context

Vitestはsrcのaliasで動き、Node下限のCIは引数なしと仕様ゲートだけを実行している。公開ワークフローはbuild後にpublishする。

## Goals / Non-Goals

配布物の準備と実行を分ける。npmやGitHubへの公開、トークンの発行、外部サービスの設定は行わない。

## Decisions

- スクリプトをprepareとcheckに分ける。prepareはpack・オフライン導入・fixture作成を行い、checkはNodeと配布物だけで主要コマンドを実行する。これによりNode下限で開発ツールを使わずに済む。
- スクリプトの検証先は新規ディレクトリとし、既存のディレクトリは上書きしない。テストが作った一時ディレクトリはテスト側で片付ける。
- publishConfig.exportsで公開時だけソース条件を除く。ワークスペース用の条件は維持する。
- 公開ワークフローでも品質検査と配布物検査を実行する。別のブランチのCI成功を根拠にしない。

## Risks / Trade-offs

パッケージの検査はビルドとインストールの時間を要する。単一の統合テストで検査し、通常のユニットテストへ重複して追加しない。NodeとOSの実際の組合せの結果はCIで確認する。
