# Design

## Context

runはprepareでブランチを操作し、開始時に秒単位の日時で記録のディレクトリを作る。単純な日時だけでは同秒の再実行で同じ場所を使う。

## Goals / Non-Goals

同じ作業ツリーを複数のrunで変更しない。別ホスト間で共有する作業ツリーの分散ロックは扱わず、他ホストのロックを自動回収しない。

## Decisions

- Gitのabsolute-git-dirに専用ファイルをwxで作る。作業ツリーを汚さず、worktreeごとのHEADを分けて扱える。所有情報はPID・ホスト名・ランダムなトークンだけとする。
- 通常の取得は既存ロックを削除しない。回復が必要な場合は別の回復用ファイルをwxで取得してから、所有者の終了を判定して回収する。これにより複数の回復処理が新しいロックを消す競合を防ぐ。
- 不明なPID、別ホスト、権限不足、回復用ファイルが残る場合は自動削除しない。所有プロセスを確認してから専用ファイルを取り除く手順を案内する。
- runRunの入口で排他し、finallyで自分のトークンが一致するロックだけを解放する。dry-runもブランチの切替を行うため排他の対象とする。
- 記録のディレクトリは排他的に作り、既存の名前があれば連番を付ける。初回の名前は維持する。

## Risks / Trade-offs

PIDの再利用では生存するプロセスを優先し、自動回収しない。回復処理そのものが強制終了した場合は手動確認が必要になる。ホスト名が同じ別PID名前空間での共有作業ツリーはサポート対象に含めない。
