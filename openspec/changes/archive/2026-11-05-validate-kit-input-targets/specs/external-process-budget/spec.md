## MODIFIED Requirements

### Requirement: 監視役が結果を書かずに終わったときの停止
監視役は対象を起動する直前にそのことを親へ渡し、起動した直後に対象のPIDを親へ渡す SHALL（Windowsでは「Windowsで対象のPIDを保持する」の保持を確かめてから、作成時刻とともに渡す）。監視役が結果を書かずに終わったか、結果を解釈できないときは、親が受け取ったPIDで対象の子孫を停止し（POSIXはグループへ同じ方法で送り、Windowsは「Windowsで監視役が結果を書かずに終わったときの子孫の識別」の方法による）、理由（監視役の終了コードかシグナル、または結果を解釈できないこと）を含む中断（ProcessLimitError）として返し、使い方の誤り（UsageError）としない SHALL。このとき同じ共有予算の後続の外部操作は起動しない SHALL。利用者の中断とは理由の有無で区別する SHALL。ただし、対象の期限に既存の停止猶予を足しても監視役が終わらず、親が強制終了し結果もない場合は、同じ後片付け・理由・後続停止を保ち、時間の上限の ProcessLimitError として返す SHALL。

Source: REQ-250, REQ-428

#### Scenario: 監視役が結果を書かずに終わる
- **WHEN** 対象の実行中に、監視役が結果を書かずに強制終了される
- **THEN** 親が対象を停止し、監視役の終了の理由を含む中断として返し、同じ共有予算の次の操作を起動しない

#### Scenario: 監視役が期限を過ぎても終わらない
- **WHEN** 監視役が対象の期限と既存の停止猶予までに結果を書かずに終わらない
- **THEN** 親が監視役を強制終了し、子孫の後片付けと理由を持つ timeout を返し、同じ共有予算の後続の外部操作を起動しない

#### Scenario: 監視役が結果を書いたあとに止まる
- **WHEN** 期限内に終わった対象の有効な結果を書いた監視役だけが終わらない
- **THEN** 親は保持を解放し、既存の正常または上限の結果を保って返す
