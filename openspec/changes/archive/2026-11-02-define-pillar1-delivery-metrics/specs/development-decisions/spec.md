# Spec Delta: development-decisions

## ADDED Requirements

### Requirement: 柱 1 の計測項目の定義
リポジトリは、柱 1 の計測項目 5 つ（実装前に見つかった確認事項の数・仕様ゲートで止まった回数・マージ後の手戻りの数・1 change あたりの時間・AI コスト）について、定義・単位・基準時点か観測期間・取得元・記録先・欠測の扱いを書いた文書を持つ SHALL。状態は記録あり・不明・非該当・観測中で区別し、記録あり以外の状態を 0 と記録してはならない MUST NOT。FR-50 の効率の表の欄との対応を書き、判断要求・試行と別の項目であることを示す SHALL。

Source: REQ-364

#### Scenario: 5 項目の定義がそろっている
- **WHEN** 定義の文書の項目の表を読む
- **THEN** 5 項目それぞれの行があり、定義・単位・基準時点か観測期間・取得元・記録先・欠測の扱いが空でない

#### Scenario: 0 と不明を区別する
- **WHEN** 状態が不明・非該当・観測中の行を検査する
- **THEN** 値が空で、理由か観測を終える日がある。値が 0 の行は状態が記録ありのものだけである

#### Scenario: FR-50 との対応
- **WHEN** 対応表を読む
- **THEN** 人の実績と費用の対応があり、確認事項の数は判断要求と、ゲートの停止は試行と別の行である

### Requirement: 柱 1 の計測の記録様式
開発効率の記録様式は、Loomake の利用の有無・比較の組・規模の欄と、5 項目それぞれの値・単位・状態・取得元・観測期間を書く節を持つ SHALL。REQ-229 の欄と、推定を書き換えない規則を保つ MUST。Loomake を使わない記録では、仕様ゲートの項目を非該当として記録できる SHALL。

Source: REQ-365

#### Scenario: 様式に柱 1 の節がある
- **WHEN** 記録様式を読む
- **THEN** 柱 1 の節に、5 項目の行と、Loomake の利用・比較の組・規模の欄がある

#### Scenario: 既存の欄を保つ
- **WHEN** 記録様式を読む
- **THEN** REQ-229 の欄はすべて残り、実績の表の 5 区分と判断根拠の内数の説明が変わっていない

#### Scenario: 実際の記録の検査
- **WHEN** `docs/effort/` の下で柱 1 の節を持つ記録を読む
- **THEN** どの行も状態が 4 つの値のどれかで、状態ごとの必須の欄がある
