## MODIFIED Requirements

### Requirement: change のブランチ
`loomake run` は、`loomake/<change-id>` のブランチで実装する SHALL。ブランチがなければいまの HEAD から作り、あればそこに切り替えて続ける SHALL。ブランチがあるときは、未コミットの変更の確認のあと、エンジンに渡すタスクを読む前にそのブランチへ切り替え、仕様ゲートとタスクの読み取りをそのブランチの内容で行う SHALL。`--dry-run` のときは、表示のあとに元のブランチへ戻す SHALL。

Source: REQ-096

#### Scenario: ブランチがない
- **WHEN** `loomake/c1` のブランチがないリポジトリで `loomake run --change c1` を実行する
- **THEN** いまの HEAD から `loomake/c1` が作られ、そのブランチでコミットされる

#### Scenario: ブランチがある
- **WHEN** `loomake/c1` のブランチがすでにあるリポジトリで `loomake run --change c1` を実行する
- **THEN** `loomake/c1` に切り替えて、その続きにコミットされる

#### Scenario: 別のブランチから再開する
- **WHEN** `loomake/c1` では 1.1 が `- [x]`、main では 1.1 が `- [ ]` のとき、main で `loomake run --change c1` を実行する
- **THEN** エンジンに 1.1 は渡されず、1.2 から渡される

#### Scenario: --dry-run の途中で失敗する
- **WHEN** main から既存の loomake/c1 に切り替えたあと、タスクの読み取り、指示の作成、表示のいずれかで例外になる
- **THEN** 例外を返す前に現在のブランチを main へ戻す

### Requirement: 実行中の失敗
`loomake run` を始める前（実行の記録を作る前）の git の失敗は、使い方の誤りとして終了コード 2 を返す SHALL。実行の記録を作ったあとに git の操作か証拠の記録が失敗したときは、`git の操作に失敗しました` などの理由と、終えたタスク・残ったタスクを表示して `summary.json` に書き、終了コード 1 で止まる SHALL。 実行の記録を作ったあと、既存の git・証拠記録・PR 公開の失敗処理でも GitError・UsageError・RuntimeFailure としても処理されず runLocked に伝わった想定外の例外は、秘密を伏せた理由、終えたタスク、残ったタスクを表示して summary.json に書き、実行中の失敗として終了コード 3 で止まる SHALL。記録の保存自体に失敗しても、秘密を伏せた保存失敗の理由を表示し、終了コード 3 を保つ SHALL。

Source: REQ-137

#### Scenario: 実行中に git のコミットが失敗する
- **WHEN** 1 つ目のタスクを終えたあと、コミットが git のフックで失敗する
- **THEN** run は止まり、理由に git の操作に失敗したことが含まれ、残ったタスクに 1 つ目のタスクがあり、summary.json に同じ内容が書かれ、終了コードは 1 である

#### Scenario: 始める前の git の失敗
- **WHEN** git のリポジトリでないディレクトリで `loomake run --change c1` を実行する
- **THEN** 実行の記録は作られず、終了コードは 2 である

#### Scenario: 想定外の例外で止まる
- **WHEN** 記録開始後の指示作成で、秘密に見える文字列を含む未分類の例外が runLocked へ伝わる
- **THEN** summary.json は stopped で、理由の秘密は伏せられ、終えたタスクと残ったタスクが書かれ、終了コードは 3 である

#### Scenario: 想定外の例外の停止記録にも失敗する
- **WHEN** 想定外の例外を停止記録に書く処理も失敗する
- **THEN** 保存できなかった理由の秘密を伏せて表示し、終了コード 3 を保つ

### Requirement: エンジンの子プロセスの停止
時間切れか中断でエンジンを止めるとき、その子プロセスも停止する SHALL。終了要求を無視するプロセスは、終了を待つ猶予を設けた後に強制終了する SHALL。開始前に中断済みの場合はエンジンを起動しない SHALL。

Source: REQ-139

#### Scenario: 子が出力先を保持する
- **WHEN** エンジンが標準出力を継承した子プロセスを起動し、時間切れになる
- **THEN** 親と子が停止し、終了待ちが子の自然終了まで続かない

#### Scenario: 終了要求を無視する
- **WHEN** POSIXのエンジンがSIGTERMを無視したまま時間切れになる
- **THEN** 猶予後に強制終了し、不合格として停止する

#### Scenario: 中断済み
- **WHEN** 起動前に中断の合図が出ている
- **THEN** エンジンを起動せず中断として返す

#### Scenario: 別セッションの子が出力先を保持したまま時間切れか中断になる
- **WHEN** POSIX のエンジンが標準出力を継承して別セッションへ離脱した子を起動し、エンジン自身が時間切れか中断になる
- **THEN** 停止の後処理と出力の猶予のあとに読み取りを打ち切って戻り、時間切れか中断の判定を保つ。離脱した子の停止は保証しない

### Requirement: 終了の信号での中断
`loomake run` は、SIGTERM と SIGHUP を受けたときも、SIGINT と同じく中断として扱う SHALL。エンジンとその子のプロセスを止め、REQ-124 と同じ記録（中断した旨の summary.json、終えたタスクのコミット、途中の変更の作業ツリー）を残してから、終了コード 1 で終わる SHALL。1 回目の信号による中断として loomake が終わったあとに、エンジンのプロセスを残さない SHALL。2 回目の信号での強制終了は REQ-427 に従う SHALL。品質コマンドや git のような同期の処理のあいだに届いた中断は、その処理が終わったところで扱い、証拠の記録・push・PR の作成に進まない SHALL。

Source: REQ-208

#### Scenario: SIGTERM で中断する
- **WHEN** 1 つ目のタスクを終えたあと、2 つ目のタスクのエンジンの実行中に、配布物の CLI が SIGTERM を受ける
- **THEN** 終了コードは 1 で、summary.json の状態は interrupted、終えたタスクは 1.1 だけで、エンジンのプロセスは残っていない

#### Scenario: SIGHUP で中断する
- **WHEN** 同じ状況で、配布物の CLI が SIGHUP を受ける
- **THEN** SIGTERM のときと同じく中断として記録し、エンジンのプロセスは残っていない

#### Scenario: 品質コマンドのあいだに中断する
- **WHEN** 完了ゲートの品質コマンドの実行中に、CLI が SIGTERM を受ける
- **THEN** 品質コマンドが終わったところで中断として止まり、終了コードは 1 で、push も PR の作成もしない

#### Scenario: 既存の PR の検索のあいだに中断する
- **WHEN** 既存の PR の検索の実行中に、CLI が SIGTERM を受ける
- **THEN** 検索が終わったところで中断として止まり、PR を作らない

### Requirement: 通常終了したエンジンの子の後処理
POSIXでは、エンジンのプロセスが終了したあとにも同じプロセスグループに残る子を停止し、後処理を待ってからエンジンの呼び出しを完了する SHALL。終了要求を無視する子は猶予後に強制終了する SHALL。後処理だけを理由に、エンジン自身の終了コード、出力、時間切れ・中断・出力上限の判定を変えない SHALL。この追加保証は同じPOSIXプロセスグループに限り、別のセッションに離脱した子とWindowsでの通常終了後の子の停止は含まない SHALL。既存の明示停止時の処理は維持する SHALL。 別セッションへ離脱した子が出力先を保持していても、後処理の完了後に 250ms の猶予を置いて出力の読み取りを打ち切り、呼び出しを完了する SHALL。

Source: REQ-212

#### Scenario: 正常終了したあとに子が残る
- **WHEN** POSIXのエンジンが標準入出力を共有しない同じプロセスグループの子を起動し、その子の起動を確認してから終了コード0で終える
- **THEN** 呼び出しが戻った時点でその子は動作しておらず、その子が予定していた後からのファイル作成は起こらない

#### Scenario: 正常終了した親の子が終了要求を無視する
- **WHEN** POSIXのエンジンが、終了要求を無視してファイルの作成を予定する同じプロセスグループの子の起動を確認してから終了コード0で終える
- **THEN** 猶予後にその子を強制終了し、後処理を待ってから戻り、予定していたファイルは作られない

#### Scenario: 通常の結果を保つ
- **WHEN** POSIXのエンジンが上限内のJSON出力を返し、時間切れも中断も起きずに終了コード0で終える
- **THEN** 後処理のあとも終了コード0と出力の本文・元の出力を保ち、時間切れ・中断・出力上限超過として扱わない

#### Scenario: 非ゼロの終了コードを保つ
- **WHEN** POSIXのエンジンが上限内の出力を返し、時間切れも中断も起きずに終了コード1で終える
- **THEN** 後処理のあとも終了コード1と出力を保ち、時間切れや中断として扱わない

#### Scenario: 強制終了したあとはグループの終了を待ってから戻る
- **WHEN** POSIXのエンジンの停止でSIGKILLを送ったあと、同じプロセスグループに終了処理を終えていないメンバーが残っている
- **THEN** 自分の子はexitで回収し、孫はゾンビと消滅を「動作していない」とみなして、メンバーが動作していなくなるまで待ってから戻る。この待機は1000msを上限とし、上限を超えたらそれ以上待たずに戻る

#### Scenario: 離脱した子が出力先を保持したまま親が正常終了する
- **WHEN** POSIX のエンジンが標準出力を共有する別セッションの子を起動して正常終了する
- **THEN** 後処理と出力の猶予のあとに戻り、エンジンの終了コードと出力を保ち、後処理だけで時間切れか中断として扱わない

## ADDED Requirements

### Requirement: 2 回目の信号での強制終了
`loomake run` は SIGINT・SIGTERM・SIGHUP のいずれかを受けたあと、もう一度いずれかを受けたら、1 回目の中断処理（プロセスの停止、記録の保存）の完了を待たずに、2 回目に実際に受けた信号の 128+番号（SIGINT=130、SIGTERM=143、SIGHUP=129）を終了コードとして終わる SHALL。異なる種類の信号も通算して 2 回目とする SHALL。同期の処理中に届いた信号は、その処理が終わって信号ハンドラーを実行できるところで扱う SHALL。1 回目の信号の扱い（REQ-124・REQ-208）は維持する SHALL。この強制終了では summary.json の作成、エンジンとその子の停止の完了、実行ロックの解放を保証しない。

Source: REQ-427

#### Scenario: 同じ信号を 2 回受ける
- **WHEN** run が SIGINT を受け、中断処理が終わる前にもう一度 SIGINT を受ける
- **THEN** 中断処理の完了を待たず、終了コード 130 で終わる

#### Scenario: 異なる信号を 2 回受ける
- **WHEN** run が SIGTERM のあとに SIGHUP を受ける
- **THEN** 信号を通算し、終了コード 129 で終わる
