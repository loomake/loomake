## ADDED Requirements

### Requirement: 合意した品質 YAML の差分だけを反映して既存の内容を保つ
Skill は、合意前には quality.yaml を書かず、具体的に合意した差分だけを反映するよう定める SHALL。合意した既存値・ID の更新は可能とし、合意対象外の値・コメント・未知キー・順序・ID は保持する。新規 ID は同じ接頭辞の既存最大番号の次から採番し、無断で振り直さない。未合意の変更が必要な場合、予期しない新 ID 衝突、読取不能や version/model 不正は、書き換えず関連 REQ つき Q にする。全面再整形はせず、不在時は合意した全文を新しく書き、既存を上書きする init は使わない。

Source: REQ-410

#### Scenario: 合意前は書かず合意した更新だけを書く
- **WHEN** 品質 YAML の反映手順を読む
- **THEN** 合意前には書かず、合意した既存値・ID の更新も含む具体差分だけを反映する指示がある

#### Scenario: 合意対象外の内容を例で保持する
- **WHEN** 書式の参照ファイルの変更前・変更後を比較する
- **THEN** 合意した既存値の更新があり、合意対象外の行は同じ内容・順序で残り、既存 ID の対象外の値と未知キーは解析しても変わらない

#### Scenario: 書き換えられない条件で止まる
- **WHEN** 未合意の変更が必要、新規追加 ID が予期せず衝突、または YAML が読めないか version/model が不正である
- **THEN** 無断の再採番・全面再整形や書き換えをせず、関連 REQ つき Q にする指示がある

#### Scenario: ファイル不在時に合意した全文を作る
- **WHEN** quality.yaml がない
- **THEN** 合意した新規全文で作り、既存を上書きする init は実行しない指示がある
