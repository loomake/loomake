# Design

## Context

動機は proposal.md を参照。`runInit` は安全な配置先かを調べ、差分を集め、確認結果の集合に従って書き込む。既存の `.gitignore` 追記と、作成・上書きに応じた案内はこの書き込みのあとにある。

Opus の設計成果に基づく。実行情報は PR の証跡に記録する。

## Goals / Non-Goals

確認を省く場合も既存の書き込みと後処理を共用する。リンク先の保護と通常の TTY での確認を維持する。prompt の EOF 処理全般は扱わない。

## Decisions

- `InitOptions.existingFiles` を省略可能な `'ask' | 'overwrite' | 'keep'` とし、省略時は ask。真偽値を二つ持つ方式より、API の相互排他を型で表せる。
- CLI は `--yes` と `--keep-existing` の同時指定を `runInit` より前に `UsageError` で拒否する。TTY でも明示オプションを優先する。
- モードによらず安全な配置先かを先に調べる。差分はどのモードでも表示し、overwrite は全件を上書き集合へ加え、keep は集合を空にし、ask だけ確認する。
- `.gitignore` への追記は維持する。keep では保持した設定の `tests.report` を採用する。品質雛形や commands の案内は実際に書いた場合だけ出す。
- CLI 基準の原本は変えず、Q-407-01 を出典とする具体差分を登録する。生成リファレンスは共通定義から再生成する。
- REQ-023・396・397 の無指定での中止シナリオに、両オプション無指定の前提を足す。既存の本文と他のシナリオは保持する。

## Risks / Trade-offs

`--yes` はカスタム設定もテンプレートで上書きする。CLI ヘルプ・導入案内で意味を明記し、残す場合の `--keep-existing` を案内する。差分の表示量は既存と同じで、変更する出力を限定する。
