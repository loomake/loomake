# 設計：回答済み確認事項IDの全体照合

## Context

Opus設計（2026-11-02、fb52ad3e-b411-4b8f-b846-3012ae743fe5）を再利用する。元設計の未決Q-327-01は2026-11-03に利用者がAを回答した。問題と範囲はproposal.mdに示す。

## Goals / Non-Goals

checkSpecの参照検出だけを変更し、relatedIds・SHARED_MARK・core parser・format・doneは変更しない。主仕様の既存5 Scenarioを差分仕様に保持する。

## Decisions

自changeの確認事項から非空のIDを重複なく集め、長い順に並べる。未回答のIDも含め、回答済みかは既存のansweredIdsで判定する。各行を左から走査し、前後がASCII英数字・ハイフン以外で、文字列として一致する最長IDを採る。採ったIDの長さだけ進み、回答済みのときだけ既存形式の参照を積む。

正規表現をIDから組み立てないため、Q.1などの記号も文字どおりに扱える。空IDを除外して走査の停止を保証する。既存のsplitLinesとfenceMaskを使い、CRLFと両種のコードブロック除外を維持する。ファイル・行・行内位置の順と繰り返しを保つ。他changeの明記は意味解析せず、インラインコードやリンクも従来どおり文字列として扱う。

境界AはQ-15A・Q-15-01の短いIDの誤案内を防ぎ、Q-17の回答という日本語隣接を維持する。dot・underscoreの特例とUnicode文字の除外は採らない。

## Risks / Trade-offs

候補数に比例した文字列比較が増える。既存の読取り予算や探索範囲は維持し、新たな全文解析や依存を追加しない。未回答の長い既知IDも先に採ることで、回答済み短縮IDの誤案内を防ぐ。

## Verification

修正前に新しいREQ-360試験の失敗を保存し、最小修正後に既存試験と合わせて確認する。長いID、未知/未回答の長いID、一般文字列ID、ASCII境界、記号・重なり・順序・繰り返し・CRLF・両フェンス・doneを確かめる。既存の試験・期待値・期限・skip・設定は変更しない。
