# Design

## Context

recordAndOpenPrは完了ゲートの後に必ずrunRecordと証拠コミットを実行する。pushやgh pr createの失敗を記録するが、次の実行は証拠を再生成する。PR作成前の検索はない。証拠には検証対象の親SHAと、trace.md・差分仕様のスナップショットがある。

## Goals / Non-Goals

完了した検証と実装を保ちながら、外部操作の失敗から再試行できるようにする。過去の任意の証拠や、コード変更後の古い証拠は再利用しない。実際のGitHub接続をローカルの代替試験で確認したとは扱わない。

## Decisions

- GitのNUL区切りのdiff-treeで、直前のコミットが対象の証拠1ファイルの追加だけで、親が1つあることを確認する。候補のパスは既存の証拠名に限定する。
- traceは既存のevidenceProblemとreadDocuments・changedDocumentsを公開する。runnerは同じ検証を再実装せず、候補の合格・親SHAと文書の一致を確認する。旧証拠のdocuments省略はreportでは維持するが、自動再利用の候補としては受け付けない。
- 完了ゲートの前後でHEADが動いたら止まる。再利用前には作業ツリーが未変更であることも確認する。通常のゲートタスクのチェックとコミットは既存の手順を維持する。
- 新規の状態ファイルは作らず、Gitと証拠の内容から再利用できるかを判定する。候補がない場合は従来のrunRecordを使う。候補の内容が不正なら、記録を増やす代わりに確認を促す。
- pushの後にgh pr listをbase・head・open・limit 2とJSONの指定で実行する。別リポジトリのPRや想定外の枝は自動採用せず止まる。0件なら作成、1件なら再利用、複数件や不正な結果は停止する。
- 作成後のURLも検証する。応答不明の作成失敗はその実行を停止し、次の実行の検索で既存PRを確認する。新規作成と既存利用を実行記録で区別する。

## Risks / Trade-offs

証拠の再利用条件は直前の証拠だけに限るため、途中に無関係なコミットが入ると新規に記録する。Gitと証拠の整合性は発行者の真正性を保証しない。別クライアントが検索と作成の間に同時操作する競合はGitHubの作成エラーとして扱い、次の実行で検索する。ghの出力形式が変わった場合は推測で作成へ進まない。
