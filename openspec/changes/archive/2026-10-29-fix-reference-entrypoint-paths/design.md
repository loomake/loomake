# Design

## Context

問題と対象範囲はproposalを参照する。main `03ff6057845e6e5bcb1bb1d2ba086db9def83126` の生成器は`resolve(process.argv[1])` と `fileURLToPath(import.meta.url)` を文字列で比較する。前者は親ディレクトリのリンクを残し、Nodeが解決した後者は実体を指すため、同じファイルでも起動判定が一致しない。

[macOS shard2の失敗](https://github.com/loomake/loomake/actions/runs/40844515674/job/123348619751)では、既存REQ-321試験の欠落checkが期待1に対して0だった。同じmainの無変更スクリプトをLinuxの明示的なディレクトリsymlink経由で起動して再現した。これを#116の時間切れと混同しない。macOS実機とWindowsでの修正後の実行は後続のCIで確認する。

## Goals / Non-Goals

**Goals:** 直接起動かどうかの判定だけを直し、既存の引数検証と生成・照合関数へ処理を渡す。パスの表記差を理由に処理せず成功したと返す不具合を防ぐ。

**Non-Goals:** スキーマの読取先、生成先、描画内容、改行の扱い、引数、診断と終了コードは変えない。Nodeの起動オプションや製品CLIへ新しい機能を追加しない。

## Decisions

### 同じ実体へ解決してから直接起動かどうかを判定する

Node標準のrealpathで起動引数とモジュールのパスを同じ実体へ解決し、直接起動かを比較する。ルートの算出とrunQualityReferenceCommandへの引数の受け渡しは維持する。cwdを変更したり、OSごとの文字列置換で `/private` を除いたりする方法は、別のパスへ誤一致するため採らない。生成関数の無条件呼出しはimportに副作用を持ち込むため採らない。

`process.argv[1]` がないimportでは起動しない。別モジュールからのimportで起動引数の実体を解決できない場合も、直接起動の判定だけで例外や診断を発生させない。生成・照合を開始したあとの読取失敗は、既存のrunQualityReferenceの失敗処理を保つ。

### 実際にリンクを通る子プロセスで回帰を確かめる

実体のfixtureディレクトリと別名の親ディレクトリを用意し、Linux/macOSではsymlink、Windowsではjunctionを使う。リンクのパスをprocess.execPathに渡して子プロセスを起動する。別cwdから欠落check1、不明引数2、通常生成0、一致check0、改変check1と非書込を確認する。物理パスの既存試験は保持する。

importの確認も別プロセスで行う。起動ファイルが別のwrapperの場合と、起動ファイル引数がない場合に、実体・リンク経由のimportで生成物、標準出力、標準エラー、呼び出し元の終了コードが変わらないことを確かめる。試験名にはREQ-321を付ける。

fixtureの作成先は専有領域を使い、リンクだけを先に外してから実体を片付ける。リンク作成に失敗した場合は試験を失敗させ、skipや物理パスへの置換で回避しない。

## Risks / Trade-offs

- 実体への解決はファイルシステムを参照する。直接起動の判定に閉じ、import時の判定失敗が呼出し元へ漏れないことを試験する。
- Windowsのリンク作成には環境差がある。ディレクトリjunctionを使い、既存のWindows CIで実行する。Linuxでの再現だけをWindows/macOSの成功とは扱わない。
- 未マージPR #144にも別の生成器がある。本changeへ混ぜず、管理役が別途扱う。

## Migration Plan

既存の生成器と試験だけを変更し、利用者の設定や生成ページの移行は不要とする。既存テスト・設定を保ったまま関連試験と完了ゲート、対象headの必須CI、独立レビューを確認する。問題があれば修正コミットを戻し、生成済みページを別の内容へ置き換えて検査を通さない。公開やリリースは行わない。
