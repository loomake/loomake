## ADDED Requirements

### Requirement: 終了コード 0 のエンジンの結果の異常
エンジンが終了コード 0 で終え、中断・上限・質問・HEADやブランチの変更・Git内部の変更がないとき、`loomake run` は出力保存後に `runClaude` が受け取った元の標準出力を REQ-341 で分類する SHALL。失敗か形の異常なら、不正な直し方の検査と表示を通常どおり行い、タスクも完了ゲートのタスクも完了にせず、コミット・変更不要の完了・完了ゲートの再実行・後続のエンジン呼出しをせず、状態 `stopped` と終了コード 1 で止まる SHALL。変更は index から外して作業ツリーに残す SHALL。理由は、失敗か形の異常かと、表示できる subtype と、当該 `NN-output.json` の具体的なパスを先頭に置き、不正な直し方もあればその後に続ける SHALL。理由にはこれら以外の result や標準出力の内容を含めない MUST。パス全体は通常の summary.json と表示に残し、REQ-179 の別形式と、分類後の summary/stop 保存失敗では、その短い本文に従う SHALL。

Source: REQ-340

#### Scenario: 失敗の結果で変更を残す
- **WHEN** エンジンが 1.1 のタスクでファイルを足し、`is_error` が true、`subtype` が `error_max_turns` の結果を終了コード 0 で返す
- **THEN** 1.1 は `- [ ]` のまま、コミットは増えず、ファイルは作業ツリーに残り、index は空で、表示と summary.json の reason に `error_max_turns` と `01-output.json` のパス全体が含まれ、終了コードは 1 である

#### Scenario: 結果の異常と不正な直し方
- **WHEN** エンジンが tests/a.test.ts を消し、`is_error` が true の結果を終了コード 0 で返す
- **THEN** 削除と差分と承認のしかたが表示され、理由は結果の異常の後に不正な直し方が続き、コミットは増えず、終了コードは 1 である

#### Scenario: 読めない結果と変更不要の合図
- **WHEN** エンジンが何も変えず、JSON でない標準出力に `LOOMAKE-NOCHANGE: 済み` の行を出して終了コード 0 で終える
- **THEN** タスクは完了にならず、コミットは増えず、理由に結果を読めないことが含まれ、終了コードは 1 である

#### Scenario: 先に止まる条件を保つ
- **WHEN** エンジンが `is_error` が true の結果を終了コード 1 で返すか、フックを書いて `is_error` が true の結果を終了コード 0 で返す
- **THEN** 前者は終了コードの理由で、後者は git add・git commit をせずにGit内部の変更の理由を先にして止まる

#### Scenario: 理由に本文を含めない
- **WHEN** エンジンが、`result` と知らない欄に同じ目印の文字列を入れ、`is_error` が true、`subtype` が `error_max_turns` の結果を終了コード 0 で返すか、その目印を含む JSON でない標準出力を終了コード 0 で返す
- **THEN** 表示と summary.json の reason に目印は含まれず、前者の理由は `error_max_turns` と `01-output.json` のパスを含み、出力の記録には目印が残る

#### Scenario: 停止情報の短い本文に収まるパス
- **WHEN** 結果の異常と多数の不正な直し方で止まって summary が予約量を超え、実行の記録のパスが短い本文に収まる長さである
- **THEN** stop.json の reason は 2048 文字以下で、先頭に結果の異常があり、`01-output.json` のパス全体を含む

#### Scenario: 短い本文を超える長いパス
- **WHEN** 同じ状況で、実行の記録のパスが短い本文の上限を超えるほど長い
- **THEN** stop.json の reason は 2048 文字以下で、先頭に結果の異常があり、パス全体を含むことは求めない

#### Scenario: 保存できないときの表示
- **WHEN** 結果を分類したあと、その異常で止める summary/stop 情報の保存で I/O エラーが起きる
- **THEN** 表示は保存できないことと確認先を示し、止めた理由の短い本文の先頭に結果の異常がある

## MODIFIED Requirements

### Requirement: タスクごとのコミット
エンジンがタスクを終え、REQ-340 で止まらず、変更を残したか、変更不要の合図と理由を出したとき、`loomake run` は tasks.md のそのタスクを `- [x]` にし、エンジンの変更と合わせて `run(<change-id>): <タスクの番号と本文>` のメッセージでコミットする SHALL。tasks.md のタスクを完了にするのは run であり、エンジンではない SHALL。エンジンが 0 以外の終了コードで終わったとき（終了コードが得られないときを含む）は、そのタスクを完了にせず、コミットもせずに、終了コードを理由として止まる SHALL。

変更も変更不要の合図と理由もなければ、REQ-330 に従い未完了のまま止まる SHALL。

Source: REQ-099

#### Scenario: タスクを終える
- **WHEN** エンジンが 1.1 のタスクでファイルを 1 つ足して終える
- **THEN** そのファイルと、1.1 を `- [x]` にした tasks.md が、`run(c1): 1.1 …` のメッセージで 1 つのコミットになる

#### Scenario: エンジンが失敗する
- **WHEN** エンジンが 1.1 のタスクで終了コード 1 で終わる
- **THEN** 1.1 は `- [ ]` のままで、コミットは増えず、run は終了コード 1 で止まる

#### Scenario: 失敗の結果を返す
- **WHEN** エンジンが 1.1 のタスクでファイルを足し、`is_error` が true の結果を終了コード 0 で返す
- **THEN** 1.1 は `- [ ]` のままで、コミットは増えず、ファイルは作業ツリーに残り、index は空で、終了コードは 1 である

### Requirement: 変更を残さずに終えたタスク
エンジンがタスクで終了コード 0 のまま終え、質問・HEADやブランチの変更・Git内部の変更・REQ-340 の結果の異常・不正な直し方のどれもないとき、`loomake run` は、run がそのタスクを完了にする前の時点で、エンジンの変更が index にあるかを調べる SHALL。調べる対象は、不正な直し方の検出と同じ `git add -A` 後の index とし、`.gitignore` で除外したファイルは含めない SHALL。変更がなく、エンジンの出力に `LOOMAKE-NOCHANGE:` で始まり空でない理由を持つ行もなければ、そのタスクを完了にせず、コミットもせずに、状態 `stopped` と終了コード 1 で止まる SHALL。止まるときは、エンジンが変更を残さずに終わったことと、エンジンの出力の記録の場所と、権限や環境を見直して実行し直すか、変更が要らないなら人が tasks.md のそのタスクを完了にしてコミットしてから実行し直すことを表示する SHALL。

Source: REQ-330

#### Scenario: 何も変えずに終える
- **WHEN** エンジンが 1.1 のタスクで何も変えず、`LOOMAKE-NOCHANGE:` の行も出さずに終了コード 0 で終える
- **THEN** 1.1 は `- [ ]` のままで、コミットは増えず、エンジンはそれ以上呼ばれず、エンジンが変更を残さずに終わったことと対処が表示され、summary.json の status は `stopped`、終了コードは 1 である

#### Scenario: 行頭にない合図と理由のない合図
- **WHEN** エンジンが何も変えず、`引用 LOOMAKE-NOCHANGE: 例` か、理由のない `LOOMAKE-NOCHANGE:` だけを出力して終える
- **THEN** 合図とはみなさず、何も変えずに終えたときと同じに止まる

### Requirement: 変更が要らないタスクの合図
エンジンがタスクで変更を残さず、REQ-340 で止まらず、出力に `LOOMAKE-NOCHANGE:` で始まり空でない理由を持つ行があれば、`loomake run` は最初の行の理由を `maskSecrets` で置換したうえで標準出力と run のコミット本文に残し、tasks.md だけのコミットでそのタスクを完了にする SHALL。変更があれば、その行の有無にかかわらず、REQ-099 に従いタスクを完了にしてコミットする SHALL。`LOOMAKE-QUESTION:` の行もあれば、質問で止まる SHALL。タスクの指示には、変更が要らないときは何も変えずに `LOOMAKE-NOCHANGE:` で始まる行に理由を書いて終えることと、変更もこの行もなければ run が止まることを、決まりとして含める SHALL。

Source: REQ-330

#### Scenario: 変更が要らないと合図する
- **WHEN** エンジンが 1.2 のタスクで何も変えず、`LOOMAKE-NOCHANGE: 1.1 で済んでいます` を出力して終える
- **THEN** その理由が `maskSecrets` で置換されて標準出力とコミット本文に残り、tasks.md だけを含む `run(c1): 1.2 …` のコミットで 1.2 が `- [x]` になる

#### Scenario: 変更と合図が両方ある
- **WHEN** エンジンがファイルを足し、`LOOMAKE-NOCHANGE:` の行も出力して終える
- **THEN** そのファイルと tasks.md が `run(c1): …` で 1 つのコミットになる

#### Scenario: 質問と合図が両方ある
- **WHEN** エンジンが何も変えず、`LOOMAKE-QUESTION:` と `LOOMAKE-NOCHANGE:` の行を出力して終える
- **THEN** 質問が表示され、タスクは未完了のまま、終了コードは 1 である

#### Scenario: 指示に合図の決まりを含める
- **WHEN** `loomake run --change c1 --dry-run` で最初のタスクの指示を表示する
- **THEN** 指示に `LOOMAKE-NOCHANGE:` の決まりが含まれる

#### Scenario: 失敗の結果と合図
- **WHEN** エンジンが 1.1 のタスクで何も変えず、`LOOMAKE-NOCHANGE: 済み` を result に含め、`is_error` が true の結果を終了コード 0 で返す
- **THEN** 1.1 は未完了のまま、コミットは増えず、「変更不要としてタスクを完了にします」は表示されず、理由に `01-output.json` のパスが含まれ、終了コードは 1 である

### Requirement: 変更を残さない完了ゲートの直し
完了ゲートの直しで、エンジンが終了コード 0 のまま終え、質問・HEADやブランチの変更・Git内部の変更・REQ-340 の結果の異常・不正な直し方のどれもなく、index に変更もないとき、`loomake run` は完了ゲートを実行し直さずに、状態 `stopped` と終了コード 1 で止まる SHALL。エンジンの出力に `LOOMAKE-NOCHANGE:` の行があっても止まる SHALL。止まるときは、直しでエンジンが変更を残さずに終わったことを理由とし、完了ゲートのタスクは完了にしない SHALL。直しの指示には `LOOMAKE-NOCHANGE:` の決まりを含めない SHALL。

止まるときの理由には、その直しで呼んだエンジンの出力の記録（`NN-output.json`）の具体的なパスを、タスクの段階で止まるときと同じ形で含める SHALL。

Source: REQ-331

#### Scenario: 直しで何も変えない
- **WHEN** `run.maxFixes` が既定の 5 で、1 回目の完了ゲートに不合格になり、直しのエンジンが何も変えずに終える
- **THEN** エンジンは直しで 1 回だけ呼ばれ、直しでエンジンが変更を残さずに終わったことが報告され、完了ゲートのタスクは `- [ ]` のまま、終了コードは 1 である

#### Scenario: 直しで変更が要らないと合図する
- **WHEN** 直しのエンジンが何も変えず、`LOOMAKE-NOCHANGE: 直すところがありません` を出力して終える
- **THEN** 完了ゲートを実行し直さずに止まり、終了コードは 1 である

#### Scenario: 直しの指示
- **WHEN** 完了ゲートに不合格になり、直しの指示をエンジンに渡す
- **THEN** 直しの指示に `LOOMAKE-NOCHANGE:` の決まりは含まれない

#### Scenario: 直しで止まるときの記録の場所
- **WHEN** 1 回目の完了ゲートに不合格になり、3 回目のエンジンの呼び出しに当たる直しが何も変えずに終える
- **THEN** 表示と summary.json の reason に、その実行の記録の `03-output.json` のパスが含まれ、そのファイルがある

#### Scenario: 直しで読めない結果
- **WHEN** 直しのエンジンが何も変えず、JSON でない標準出力を終了コード 0 で返す
- **THEN** 理由は REQ-340 の結果を読めないことで、直しで変更を残さずに終わったことではなく、完了ゲートを実行し直さず、終了コードは 1 である

### Requirement: 完了ゲートと直し
すべてのタスクを終えたら、`loomake run` は完了ゲート（`verify --done` と同じ検査）を実行する SHALL。不合格なら、不合格の内容をエンジンに渡して直させ、REQ-340 で止まるか、変更がなく REQ-331 に従うときは、コミットも完了ゲートの再実行もせずに止まり、それ以外で変更があるときは直しを `run(<change-id>): 完了ゲートの直し（N 回目）` でコミットしてから、もう一度完了ゲートを実行する SHALL。完了ゲートのタスクはエンジンに渡さず、完了ゲートに合格したときに run が完了にする SHALL。完了ゲートのタスクは、行に `<!-- loomake:gate=done -->` の印があるタスクとする SHALL。印のないタスクでも、本文に `verify` と `--done` を含むものは旧書式の完了ゲートのタスクとみなし、印を付けるよう案内を表示する SHALL。エンジンへの指示とコミットのメッセージには、印を除いたタスクの文を使う SHALL。

Source: REQ-100

#### Scenario: 直して合格する
- **WHEN** 1 回目の完了ゲートに不合格になり、エンジンが直したあとの 2 回目で合格する
- **THEN** エンジンへの 2 回目の指示に 1 回目の不合格の内容が含まれ、直しが「完了ゲートの直し（1 回目）」でコミットされ、完了ゲートのタスクが `- [x]` になる

#### Scenario: 完了ゲートのタスクはエンジンに渡さない
- **WHEN** tasks.md の最後のタスクが「`pnpm -s verify --change c1 --done` を通す」の change を実行する
- **THEN** そのタスクはエンジンに渡されない

#### Scenario: 印のあるタスク
- **WHEN** tasks.md の最後のタスクが「品質の確認を通す <!-- loomake:gate=done -->」の change を実行する
- **THEN** そのタスクはエンジンに渡されず、完了ゲートに合格したときに `- [x]` になる

#### Scenario: 旧書式のタスク
- **WHEN** 印がなく、本文が「`pnpm -s verify --change c1 --done` を通す」のタスクを持つ change を実行する
- **THEN** そのタスクはエンジンに渡されず、行に `<!-- loomake:gate=done -->` を付けるよう案内が表示される

#### Scenario: 印は指示とメッセージに含めない
- **WHEN** 印のある完了ゲートのタスクを持つ change で、完了ゲートに不合格のまま直しの回数の上限に達して止まる
- **THEN** 残ったタスクの表示と summary.json の完了ゲートのタスクに `<!-- loomake:gate=done -->` が含まれない

#### Scenario: 直しのエンジンが失敗の結果を返す
- **WHEN** 1 回目の完了ゲートに不合格になり、直しのエンジンがファイルを変えて、`is_error` が true の結果を終了コード 0 で返す
- **THEN** 直しはコミットされず、完了ゲートは実行し直されず、完了ゲートのタスクは `- [ ]` のまま、変更は作業ツリーに残り、終了コードは 1 である
