# Design

## Context

kit・trace・runnerに再帰探索とreadFileSyncの重複がある。statSyncはリンク先をたどるため、specsの循環を止める条件がない。テストレポートと証拠もサイズを確認せず一括読み取りし、reportは全証拠を同時に保持する。

## Goals / Non-Goals

共通の入力予算と型の確認を導入し、成功・異常・境界を直接試験できるようにする。累積ディスク容量やプロセスの隔離、すべての外部操作の時間予算はこの変更の対象にしない。

## Decisions

- kitにcreateInputReaderと文書・JSONの既定値を置く。coreは純粋なモデルと解析に保ち、既存のパッケージ依存方向を維持する。UsageErrorをerrors.tsへ分け、configからの従来のexportを維持して循環依存を避ける。
- 文書は1MiB・合計16MiB、JSONは64MiB・合計128MiB、探索は4096項目・深さ32とする。公開APIで小さい予算も指定できるが、CLIの設定に緩和項目は追加しない。
- opendirで逐次列挙して項目を数え、上限以内の結果だけを整列する。lstatで探索中のリンクを拒否し、深さを明示して循環と過大な探索を止める。verifyの従来の除外をオプションで維持する。
- ファイルのlstat、open、fstatで通常のファイルを確認し、固定サイズのチャンクで読み、実際のバイト数を数える。対応するOSではNOFOLLOWとNONBLOCKも使い、finallyで閉じる。OSをまたぐ同時ファイル差し替えの完全な隔離は保証しない。
- 各呼び出しで共有するreaderを渡し、文書や証拠の合計を数える。reportは逐次検証し、最新の証拠だけを保持する。古い不正な証拠も黙って無視しない。
- ファイル読み取りの予算と別に、buildPromptで生成した指示全体をUTF-8のバイト数で16MiBまでに制限する。検証の失敗情報はファイルのreaderを通らないため、送信前にも全体を確認する。
- プロジェクトルートのリンクは既存のrealpath処理などを維持する。探索で見つかった子のリンクと、最終要素がリンクのファイルを拒否する。信頼した設定が指すパスの全祖先を、OSの隔離として検証する仕組みにはしない。

## Risks / Trade-offs

今まで読めた過大な入力は明示的なエラーになる。リンクでspecsを組み合わせていた場合も、通常のファイルとして配置する必要がある。JSON解析後のオブジェクトには追加のメモリが必要であり、バイト上限はプロセス全体のRSSの厳密な上限ではない。深さと項目数は読み取り処理内の訪問量として数える。
