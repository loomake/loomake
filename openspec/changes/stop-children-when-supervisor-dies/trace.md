| A-01 | REQ-250 | 監視役が結果を書かずに終わったときは、kind を `interrupted` にし、理由を `reason` とメッセージに入れる。新しい kind は足さない | 外からの強制終了（Windows の `process.kill(pid, 'SIGINT')`）は、利用者や上位の処理による中断と同じに扱い、後続の操作を止めるのが安全。既存の呼び出し元（verify・run）は kind で分岐しているので、新しい kind を足すと分岐の漏れが起きる。利用者の中断とは `reason` の有無とメッセージで区別できる | | | |
| A-02 | REQ-250, REQ-252 | PID の再利用は扱う（Q-02 の回答で変更）。Windows では、監視役が対象を起動する直前と直後の時刻を作成時刻の範囲として親へ渡す。親はプロセスの一覧の作成時刻と親の PID で対象とその子孫を識別し、止める直前にハンドルを開いて作成時刻を確かめ、ハンドルを持ったまま止める。同一性を確認できないものは止めず、理由を中断の理由に入れる。ただし、対象が終わったあとに別のプロセスが同じ PID を取って子を作り、すでに終わっている場合、その子は作成時刻の範囲と親の PID では対象の子と区別できず、止めてしまう（PR #22 のレビュー r4384461918、P1）。これは REQ-252 の「同一性を確認できないプロセスを推測で止めない」に反するので、帰属を確かめる方法を Q-04 で決め、この仮定を改める。Q-04 の途中の回答に従い、実行ごとの印（環境変数）で帰属を確かめる A を検証している（design.md）。POSIX はプロセスグループへ送るので、グループに生きたメンバーがいる限り再利用されない | 対象の正確な作成時刻を起動時に知るには、Windows では PowerShell などを毎回起動する必要があり、通常の run が遅くなる。起動の直前と直後の時刻で挟めば、通常の run は変えずに、再利用したプロセスと区別できる | | | |
