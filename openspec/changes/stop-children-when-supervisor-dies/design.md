# Design

## Context

Windows で監視役が強制終了すると、監視役が shell で起動した cmd.exe も一緒に終わり、cmd.exe が起動した品質コマンドが親のいない状態で残る（run 40242169987、PR #24 の run 40243055420）。libuv は Windows で detached でない子を job object に入れ、job が閉じると中のプロセスを止める一方、子が起動したプロセスは job から外れるように設定する、という推定で、CI では確かめていない。親が受け取った PID は cmd.exe のものなので、`taskkill /pid <PID> /T` は not found で失敗し、孫に届かない。対象が Node のときは、対象自身の job が閉じて孫も止まるので、process.test.ts の試験は通っている。

レビューの回答（Q-02）で B 案を基本にすることになった。通常の run の起動の仕方は変えず、監視役が結果を書かずに終わったときの後片付けだけを変える。

## Decisions

### 対象の識別情報

監視役は対象を起動する直前と直後に `Date.now()` を読み、対象の PID と一緒に fd 3 へ先に書く（`{ pid, from, to }`）。正確な作成時刻を起動時に得るには Windows で PowerShell などを毎回起動する必要があり、通常の run が遅くなるので、起動の直前と直後の時刻で挟む（A-02）。親は監視役の終了を受け取った直後の `Date.now()` も記録する（`observedAt`）。

### Windows の後片付けの流れ

監視役が有効な結果を書かずに終わり、対象の PID を受け取っているときだけ、親は次の順に進める。全体の期限は開始から 10 秒で、各手順には残り時間だけを渡す。候補の数によって期限を延ばさない。

1. 一覧の取得。PowerShell の `Get-CimInstance Win32_Process` で、PID・親の PID・作成時刻（UTC の 100ns 単位）を取得する。失敗と時間切れは区別して返す
2. 識別（`planOrphanCleanup`、純粋な関数）。次の規則で根と子孫を決める
   - 対象の PID を持つプロセスの作成時刻が `[from - 50ms, to + 50ms]` にあれば、対象は動いているとして、対象を根にする
   - そうでなければ対象は不在とし、PID が使われていれば再利用とする。親の PID が対象の PID であるプロセスのうち、作成時刻が `from - 50ms` 以後で `observedAt` 以前のものを根にする。作成時刻が `from - 50ms` より前のものは、前の PID の持ち主の子なので扱わない。`observedAt` より後のものと、再利用したプロセスの作成時刻以後のものは、同一性を確認できないとして止めず、理由を残す
   - 根から子孫をたどる。子孫は、親の PID が一致し、作成時刻が親の作成時刻以後のプロセスだけとする
3. 停止。PowerShell で各プロセスを `Get-Process -Id` で開き、`Handle` でハンドルを持ったまま `StartTime` を一覧の作成時刻と比べる（マイクロ秒の単位で）。一致しないものは、列挙のあとに PID が再利用されたとして止めない。元のプロセスは終わっているので、停止を確認できたものとみなす。一致した根には `taskkill /pid <PID> /T /F` を 1 秒まで送り、一覧のあとに増えた子孫も止める。続けて、一致したものでまだ動いているものを `Kill()`（TerminateProcess）で止める。ハンドルを持っている間は PID が再利用されないので、確かめたプロセスと止めるプロセスは同じになる
4. 待機。止めたプロセスの終了を、ハンドルで残り時間まで待つ

一覧の取得と停止の 2 回で PowerShell を起動する。識別を TypeScript の純粋な関数にして、Linux でも PID 再利用・対象不在・探索失敗・時間切れを試験できるようにするためである。一覧の取得と停止は `WindowsProcessTools` の形で差し替えられる。

### 報告

後片付けの結果は `{ confirmed, detail }` とする。停止を確認できなかったとき（一覧の取得の失敗・時間切れ・権限不足・同一性を確認できない・待機のあとも残っている）は、中断の理由に「子孫の停止を確認できません：<理由>」を加え、`ProcessLimitError.cleanup` にも結果を入れる。停止を確認できたときの理由は、これまでどおり「監視役が結果を書かずに終了しました（…）」だけにする。POSIX でも、SIGKILL のあとグループが 1 秒以内に消えなければ、停止を確認できなかったとして同じように報告する。

後片付けの結果によらず、`state.interrupted` を立て、同じ共有予算の後続の外部操作を起動しない。後片付けの 10 秒は共有予算から引かず、共有予算の期限も延ばさない。

## Verification

- Linux：`planOrphanCleanup` と `cleanupWindowsOrphans` を、差し替えた一覧・停止の結果で試験する。対象不在、PID の再利用、列挙から停止までの再利用、一覧の取得の失敗、時間切れ（全体で 10 秒、候補ごとに延ばさない）、権限不足、残ったプロセスを扱う
- Windows の CI：`[REQ-183][REQ-250] 品質コマンドの中断後に次のコマンドを実行しない` で、品質コマンド自身が消えること、後続のコマンドを実行しないことを確かめる。Windows だけで動く試験で、実際の PowerShell の一覧の取得と、ハンドルで確かめた停止を確かめる。少なくとも 3 回流す

## Risks and limits

- 作成時刻の比較は、OS の壁時計と Node の `Date.now()` が同じ時計を読むことに頼る。後片付けの間に時計が大きく動くと、対象の子を取りこぼすことがある。そのときは止めずに、同一性を確認できないと報告する
- 監視役が終わってから親が終了を受け取るまでの間に、対象の PID を再利用して子を作り、すでに終わったプロセスの子は区別できない（A-02）
- PowerShell の起動が遅い環境では、10 秒で終わらないことがある。そのときは時間切れとして報告する
