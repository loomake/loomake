# Design

## Context

Windows で監視役が強制終了すると、監視役が shell で起動した cmd.exe も一緒に終わり、cmd.exe が起動した品質コマンドが親のいない状態で残る（run 40242169987、PR #24 の run 40243055420）。libuv は Windows で detached でない子を job object に入れ、job が閉じると中のプロセスを止める一方、子が起動したプロセスは job から外れるように設定する、という推定で、CI では確かめていない。親が受け取った PID は cmd.exe のものなので、`taskkill /pid <PID> /T` は not found で失敗し、孫に届かない。対象が Node のときは、対象自身の job が閉じて孫も止まるので、process.test.ts の試験は通っている。

レビューの回答（Q-02）で B 案を基本にすることになった。通常の run の起動の仕方は変えず、監視役が結果を書かずに終わったときの後片付けだけを変える。

## Decisions

### 対象の識別情報（Q-04 の A）

親は実行ごとに 128 ビットの乱数の印を作り、監視役に渡す。監視役は、環境変数 `LOOMAKE_SUPERVISOR_MARK` の値に印を足して対象を起動する。値はセミコロンで区切った印の並びで、すでに外側の loomake の印があれば残したまま足す。こうすると、品質コマンドの中で loomake を動かしたときも、外側の後片付けで内側のプロセスを識別できる。環境変数は既定で子に引き継がれるが、子の起動時に別の環境を指定したり、変数を変えたり消したりできるので、すべての子孫が印を持つとは保証しない。監視役は、対象の PID と、起動の直前と直後の `Date.now()`（`from`・`to`）を fd 3 へ先に書く。

### Windows の後片付けの流れ

監視役が有効な結果を書かずに終わり、対象の PID を受け取っているときだけ、親は後片付けを始める。期限は、PowerShell を起動する前の時点から 10 秒とする。PowerShell の起動には残り時間を spawnSync の上限として渡し、PowerShell の中には壁時計の期限（Unix 時刻のミリ秒）を渡して、出力のための 200ms を残して手順を打ち切らせる。候補の数によって期限を延ばさない。PowerShell は 1 回だけ起動し、P/Invoke の宣言は Reflection.Emit で作る（Add-Type はコンパイルに時間がかかるので使わない）。taskkill は使わない。

1. 探索。`Process.GetProcesses()` で PID を取り、各プロセスを `PROCESS_QUERY_LIMITED_INFORMATION` で開いて、作成時刻と親の PID（ProcessBasicInformation）を読み、ハンドルを閉じる。作成時刻が `from - 50ms` より前のものは調べない。親の PID が一覧になく、または一覧の親の作成時刻が子より後なら、親はもういないとする
2. 識別。残ったプロセスを `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ | PROCESS_TERMINATE | SYNCHRONIZE` で開く（プロセスごとに 1 回だけ）。このハンドルで作成時刻を読み直し、探索の値と違えば、列挙のあとに入れ替わったとして止めない。続けて同じハンドルで環境変数を読む
   - 64 ビットのプロセス：ProcessBasicInformation の PEB から、`ProcessParameters`（PEB の 0x20、8 バイト）、`Environment`（0x80、8 バイト）を読む
   - WOW64 のプロセス（ProcessWow64Information で 32 ビットの PEB の位置が 0 でない）：32 ビットの PEB から、`ProcessParameters`（0x10、4 バイト）、`Environment`（0x48、4 バイト）を読む。32 ビットの側で環境を変えると、64 ビットの側の環境は古いまま残ることがあるので、64 ビットの側は読まない
   - 環境は、ページの境目ごとに読み進め、UTF-16 の 2 文字続きの NUL で終わる。1 MiB を超えても終わらないか、途中で読めなければ、読めないものとする
   - `LOOMAKE_SUPERVISOR_MARK` の値をセミコロンで区切り、印と完全に一致するものがあれば、止める対象にする
3. 停止。止める対象を、識別に使ったのと同じハンドルで TerminateProcess する。PID で開き直したり、子孫をまとめて止めたりしない。止めたあと、もう一度 1 と 2 を行い、新しく見つかった印のあるプロセスも止める。新しいものがなくなるか、期限に達するか、3 回目までで終える
4. 待機。止めたプロセスの終了を、同じハンドルで期限まで待つ

PowerShell は、プロセスごとに、探索の結果（PID・親の PID・作成時刻・親がもういないか）、識別の結果（印あり・別の印・印なし・読めない・入れ替わり、と理由）、開いた回数、識別・停止・待機に使ったハンドルの値、停止と待機の結果を 1 行ずつ出す。どれを未確認とするかは、TypeScript の関数で決める。

- 対象の子孫の可能性があるのは、親の PID が対象の PID か印を持つプロセスの PID のプロセスと、親がもういないプロセスで印を確かめられないもの
- 子孫の可能性があり、印がない・別の印・読めないものは、止めずに未確認とする
- 親がもういないプロセスで、印がないと読めたものは、対象の子孫かどうかを判断できないので扱わない（止めず、報告もしない）

試験では、探索の代わりに候補（PID と作成時刻）を入力で与えられるようにし、列挙からハンドルの取得までの入れ替わりを試験する。

### 対応する環境

PEB は Windows の内部構造で、将来レイアウトが変わることがある。対応するのは、x64 の Windows 10 以降で、64 ビットの PowerShell から、64 ビットのプロセスと WOW64（32 ビット）のプロセスを読む場合に限る。PowerShell が 64 ビットでないか、OS が x64 でないときは、印を確かめられないので何も止めず、未確認として返す。開けない（権限不足など）、読めない、大きさや終わりが不正、という場合も、止めずに理由を返す。

### 報告

後片付けの結果は `{ confirmed, detail }` とし、記録には探索・識別・停止・待機のそれぞれと合計の時間も残す。停止を確認できなかったとき（探索の失敗・時間切れ・権限不足・印がない・印を確かめられない・待機のあとも残っている）は、中断の理由に「子孫の停止を確認できません：<理由>」を加え、`ProcessLimitError.cleanup` にも結果を入れる。停止を確認できたときの理由は、これまでどおり「監視役が結果を書かずに終了しました（…）」だけにする。POSIX でも、SIGKILL のあとグループが 1 秒以内に消えなければ、停止を確認できなかったとして同じように報告する。

後片付けの結果によらず、`state.interrupted` を立て、同じ共有予算の後続の外部操作を起動しない。後片付けの 10 秒は共有予算から引かず、共有予算の期限も延ばさない。

## Verification

採用の前の検証は、使い捨ての PR #32（run 40446950773）で行った。cmd.exe を経た孫・WOW64 のプロセスの印の読み取りと停止、P1 の順の子と別の実行の印を持つプロセスを止めないこと、開けない・読めないプロセスの扱い、冷えた条件の時間（Reflection.Emit で 4.0〜5.0 秒）を確かめた。

製品に入れたあとの試験：

- Linux：PowerShell の出力から停止・未確認・時間切れ・探索の失敗・対応しない環境を決める関数と、期限（PowerShell の起動を含めて 10 秒、残り時間だけを渡す）を、差し替えた実行で試験する。監視役が対象の環境に印を足すこと（外側の印を残すこと）も試験する
- Windows の CI（ほかの試験と並行して動く通常の試験の中で）：
  - cmd.exe を経た孫を止める。品質コマンド自身が消え、後続の操作を始めない（`[REQ-183][REQ-250]`）
  - P1 の順：印のない親が子を作って終わったあと、その親の PID を対象として後片付けしても、その子を止めず未確認として返す
  - 64 ビットと WOW64 の cmd.exe が、起動後に印を別の値に変えた場合と消した場合に止めない。変えていない WOW64 の cmd.exe は止める
  - 列挙からハンドルの取得までの入れ替わり：作成時刻の違う候補を与えると、止めない
  - 同じハンドル：止めたプロセスについて、開いた回数が 1 回で、識別・停止・待機のハンドルの値が同じ
  - 読めないプロセス：開けない SYSTEM のプロセスを候補として与えると、止めずに理由を返す
  - 時間切れ：期限を短くすると、時間切れとして停止を確認できないと返す
  - 冷えた条件を含めて 5 回以上流し、PowerShell の起動・探索・識別・停止・待機と合計の時間を記録に残す

## Risks and limits

- 親の PID と作成時刻だけの判定は、レビューの P1（r4384461918）で帰属を確定できないことが分かったので、使わない。対象が終わる → 別のプロセスが同じ PID を取って子を作る → その親も終わる → 一覧を取る、という順で、無関係な子を止めてしまうため
- 印を持たない子孫（環境を置き換えた・印を消した）は止められない。親が対象か印を持つプロセスなら未確認として報告するが、親がもういない場合は、印がないと読めれば報告もしない
- A で条件を満たせないときは、その結果を根拠に Q-04 の B を考え直す。C（対象が不在のときの子をすべて未確認とする）は、失敗したときの安全側の扱いにとどめ、解決とはみなさない

- 探索の範囲を作成時刻で絞るのは、OS の壁時計と Node の `Date.now()` が同じ時計を読むことに頼る。時計が大きく動くと、印のある子孫を調べずに取りこぼすことがある
- PowerShell の起動が遅い環境では、10 秒で終わらないことがある。そのときは時間切れとして報告する
