# Design

## Context

Windows で監視役が強制終了すると、監視役が shell で起動した cmd.exe も一緒に終わり、cmd.exe が起動した品質コマンドが親のいない状態で残る（run 40242169987、PR #24 の run 40243055420）。libuv は Windows で detached でない子を job object に入れ、job が閉じると中のプロセスを止める一方、子が起動したプロセスは job から外れるように設定する、という推定で、CI では確かめていない。親が受け取った PID は cmd.exe のものなので、`taskkill /pid <PID> /T` は not found で失敗し、孫に届かない。対象が Node のときは、対象自身の job が閉じて孫も止まるので、process.test.ts の試験は通っている。

レビューの回答（Q-02）で B 案を基本にすることになった。通常の run の起動の仕方は変えず、監視役が結果を書かずに終わったときの後片付けだけを変える。

## Decisions

### 対象の識別情報（Q-04 の A を検証中）

Q-04 は「A の検証を進める」という推奨までで、採用は決まっていない（ブロッキングのまま）。この節は A の方式と、採用の条件を満たすかを確かめる方法を書く。

監視役は、親から受け取った実行ごとの乱数の印（128 ビットの 16 進）を、対象の環境変数 `LOOMAKE_SUPERVISOR_MARK` に入れて起動する。環境変数は既定で子に引き継がれるが、子の起動時に別の環境を指定したり、変数を消したりできるので、すべての子孫が印を持つとは保証しない。監視役は、対象の PID と、起動の直前と直後の `Date.now()`（`from`・`to`）を fd 3 へ先に書く。

### Windows の後片付けの流れ（A）

監視役が有効な結果を書かずに終わり、対象の PID を受け取っているときだけ、親は PowerShell を 1 回だけ起動し、その中で次の順に進める。全体の期限は開始から 10 秒で、PowerShell の中の手順にも残り時間だけを渡す。候補の数によって期限を延ばさない。taskkill は使わない。

1. 探索。Toolhelp のスナップショットで PID と親の PID を取り、各プロセスを開いて作成時刻を読む。作成時刻が `from - 50ms` より前のものは、対象より前からあるので調べない
2. 識別。残ったプロセスを `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ | PROCESS_TERMINATE | SYNCHRONIZE` で開き、そのハンドルで作成時刻を読み直し、PEB から環境変数を読んで印を探す。印の値が完全に一致したものだけを止める対象にする
3. 停止。止める対象を、識別に使ったのと同じハンドルで TerminateProcess する。PID で開き直したり、taskkill /T で子孫をまとめて止めたりしない。止めたあと、もう一度 1 と 2 を行い、新しく見つかった印のあるプロセスも止める。新しいものがなくなるか、期限に達するまで繰り返す
4. 待機。止めたプロセスの終了を、同じハンドルで残り時間まで待つ

次のプロセスは、対象の子孫の可能性があるので、止めずに未確認として理由を返す。対象の子孫の可能性があるのは、親の PID が対象の PID か印を持つプロセスの PID で、親より後に作られたプロセスとする。

- 印がない（環境を置き換えた・印を消した子、または P1 のように PID を再利用した別の親の子）
- 開けない・読めない（権限不足、読み取りの失敗、環境変数の大きさや中身が不正）
- 対応しない環境（下の「対応する環境」の外）

親がもういないプロセスで、印がないか読めないものは、対象の子孫かどうかを判断できないので扱わない（止めず、報告もしない）。

### 対応する環境

PEB は Windows の内部構造で、将来レイアウトが変わることがある。対応するのは、x64 の Windows 10 以降で、64 ビットの PowerShell から、64 ビットのプロセスと WOW64（32 ビット）のプロセスを読む場合に限る。PowerShell が 64 ビットでないとき、OS が x64 でないときは、印を確かめられないので何も止めず、未確認として返す。読み取りには `NtQueryInformationProcess`（ProcessBasicInformation）で PEB の位置を得て、`ReadProcessMemory` で `ProcessParameters`（PEB の 0x20）、`Environment`（0x80）、`EnvironmentSize`（0x3F0）を読む。大きさが 0 か 1 MiB を超える、UTF-16 として終わりがない、などの不正な内容は、読めないものとして扱う。P/Invoke の宣言は PowerShell の `Add-Type` か `Reflection.Emit` で作る。どちらで 10 秒に収まるかは検証で測る。

### 報告

後片付けの結果は `{ confirmed, detail }` とし、記録には探索・識別・停止・待機のそれぞれと合計の時間も残す。停止を確認できなかったとき（探索の失敗・時間切れ・権限不足・印がない・印を確かめられない・待機のあとも残っている）は、中断の理由に「子孫の停止を確認できません：<理由>」を加え、`ProcessLimitError.cleanup` にも結果を入れる。停止を確認できたときの理由は、これまでどおり「監視役が結果を書かずに終了しました（…）」だけにする。POSIX でも、SIGKILL のあとグループが 1 秒以内に消えなければ、停止を確認できなかったとして同じように報告する。

後片付けの結果によらず、`state.interrupted` を立て、同じ共有予算の後続の外部操作を起動しない。後片付けの 10 秒は共有予算から引かず、共有予算の期限も延ばさない。

## Verification

採用の前に、使い捨ての draft PR（「（使い捨て・マージしない）」、`loomake-change: none`）で、Windows の CI に次を測る。結果を PR #22 の P1 のスレッドに報告し、Q-04 のブロッキングを解いてよいかを確かめる。

- 印の読み取り：cmd.exe を経た孫（64 ビット）と、SysWOW64 の cmd.exe（32 ビット）の環境から印を読めること
- ハンドルを持ったままの停止：識別に使ったハンドルで止め、終了を待てること
- P1 の順：印のないプロセスを親として子を作り、その親を終わらせてから後片付けをすると、その子を止めずに未確認と返すこと
- 権限不足・読み取り不能：開けないプロセス（SYSTEM のプロセスなど）を、止めずに理由つきで返すこと
- 時間：PowerShell を 1 回だけ起動し、その job で最初に PowerShell を使う冷えた条件を含めて 5 回以上、探索・識別・停止・待機のそれぞれと合計の時間を残すこと。10 秒に収まること

製品に入れたあとの試験：

- Linux：PowerShell の出力の読み取りと報告（停止・未確認・時間切れ・権限不足・PowerShell の失敗）を、差し替えた実行で試験する
- Windows の CI：P1 の順、印なし、読み取り不能、識別後の PID 再利用（止めたハンドルの PID を別のプロセスが取っても止めない）、cmd.exe を経た品質コマンドの停止（`[REQ-183][REQ-250]`）を試験する。冷えた条件を含めて 5 回以上流し、各手順と合計の時間を記録に残す

## Risks and limits

- 親の PID と作成時刻だけの判定は、レビューの P1（r4384461918）で帰属を確定できないことが分かったので、使わない。対象が終わる → 別のプロセスが同じ PID を取って子を作る → その親も終わる → 一覧を取る、という順で、無関係な子を止めてしまうため
- 印を持たない子孫（環境を置き換えた・印を消した）と、親がもういない読めない子孫は止められない。前者は未確認として報告するが、後者は報告もしない
- A で条件を満たせないときは、その結果を根拠に Q-04 の B を考え直す。C（対象が不在のときの子をすべて未確認とする）は、失敗したときの安全側の扱いにとどめ、解決とはみなさない

- 探索の範囲を作成時刻で絞るのは、OS の壁時計と Node の `Date.now()` が同じ時計を読むことに頼る。時計が大きく動くと、印のある子孫を調べずに取りこぼすことがある
- PowerShell の起動が遅い環境では、10 秒で終わらないことがある。そのときは時間切れとして報告する
