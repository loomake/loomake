## MODIFIED Requirements

### Requirement: 検証済み証拠の安全な再利用
再実行でもscope:localの完了ゲートを省略しない SHALL。作業ツリーが未変更で、直前のコミットが親を1つ持ち、対象changeの証拠ファイル1つだけを追加し、その証拠の形式・対象SHA・change・scope:localの完了結果・現在の文書のスナップショットが一致するEvidence 2/verify 2.0.0に限り、外部操作の再試行に同じ証拠とコミットを再利用する SHALL。旧Evidence 1は履歴閲覧に限り、この再利用や最終CI合格に使わない MUST。候補の証拠が不正な場合は削除や上書きをせず止まる SHALL。最新コミットが別の実装や文書を変更した場合は、通常の証拠記録を行う SHALL。

Source: REQ-164

#### Scenario: pushやPR作成の失敗後に再実行する
- **WHEN** Evidence 2のlocal完了証拠のコミット後にpushまたはPR作成が失敗し、状態を変えず再実行する
- **THEN** local完了ゲートを再実行し、SHA/文書と新しいlocal結果を確認して同じ証拠とコミットで外部操作を再試行する。証拠の使い回しで品質実施やci合格を補わない

#### Scenario: 不正な証拠が直前にある
- **WHEN** 候補の証拠のJSON・SHA・合格結果・文書の対応に誤りがある
- **THEN** 証拠と作業状態を保ち、理由を示して止まる

#### Scenario: 証拠の後で実装を変更した
- **WHEN** 証拠のコミットの後に実装変更をコミットして再実行する
- **THEN** 新しい実装に対する検証と新しい証拠記録を行う

#### Scenario: 旧証拠しかない
- **WHEN** 直前の証拠がEvidence 1/verify 1.0.0である
- **THEN** 外部操作の再試行用に合格証拠として再利用せず、新しいv2検証と記録を必要とする。旧ファイルは削除しない
