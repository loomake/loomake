# 曖昧さチェックリスト

台帳の各 REQ に、次の観点を順にあてる。1 つでも答えが要件書から読み取れなければ、確認事項（Q）か仮定（A）にする。

## 言葉

- [ ] **程度を表す言葉**：「適切に」「速やかに」「十分な」「一定の」「なるべく」「など」— 数値か列挙に置き換えられるか
- [ ] **主語**：誰が行う操作か（一般利用者 / 管理者 / システム / 外部システム）
- [ ] **用語の揺れ**：同じものが別の名前で呼ばれていないか（例：「会員」と「ユーザー」）。用語集が無ければ作る
- [ ] **否定・例外**：「原則〜」「基本的に〜」の例外は何か

## 入力と出力

- [ ] **入力の範囲**：必須か任意か、最大長、文字種、空・null のときの扱い
- [ ] **件数の境界**：0 件、1 件、上限ちょうど、上限超え
- [ ] **出力の形**：並び順、ページング、日時の形式とタイムゾーン、数値の丸め
- [ ] **ファイル**：形式、文字コード、サイズ上限

## 振る舞い

- [ ] **エラー時**：何を返す / 表示するか。リトライするか
- [ ] **権限**：誰に見えて、誰が変更できるか。他人のデータにアクセスしたら
- [ ] **状態遷移**：取りうる状態と、許される遷移。取消・差し戻しはできるか
- [ ] **同時操作**：2 人が同時に更新したら。二重送信されたら
- [ ] **既存データ**：既存レコードはどうなるか（移行が要るか）
- [ ] **外部連携**：相手が落ちていたら。タイムアウトは何秒か

## 非機能

- [ ] **性能**：何件で、何秒以内か（測定条件つき）
- [ ] **ログ・監査**：何を記録し、どれだけ保持するか
- [ ] **セキュリティ**：個人情報を含むか。マスキング・暗号化が要るか
- [ ] **対応環境**：ブラウザ・端末・API のバージョン

## 文書どうし

- [ ] **他の章と矛盾していないか**
- [ ] **既存仕様（`openspec/specs/`）と矛盾していないか**
- [ ] **図と本文が食い違っていないか**

## 仮定にしてよいもの / いけないもの

仮定にしてよい：業界で一般的な既定値があり、後から変えても影響が小さいもの（ページサイズ、日時表示形式など）。

仮定にしてはいけない（必ず確認事項・ブロッキング）：

- お金・個人情報・権限に関わるもの
- データの削除・上書きに関わるもの
- 外部システムとの取り決め
- 検収条件に直結する数値（性能・件数・期限）
