# Opus へのレビュー依頼

管理役が実値に置き換えるのは、記入欄の `{{...}}` だけとする。貼った差分に含まれる `{{`・`}}` は変えない。該当しない欄には理由を書く。

依頼文の形は ADR 0006 のレビュー規則に従い、「変更差分 ＋ 変更した Requirement の ID 一覧 ＋ レビュアーが読むべきファイルの一覧（パス）」とする。通常は記入欄を埋め終えてから、`git diff <base> <head>` で全差分を取得し、差分は変えずに依頼へ貼る。Requirement の全文や呼び出し側の抜粋は貼らず、レビュアーが Read・Glob・Grep で読むファイルのパスを載せる。記入済みの依頼を専用 worktree の `.loomake/` 内へ保存し、差分を貼った依頼全体にプレースホルダーの置き換えを再び行わない。

これ以外の資料は加えない。外部の資料が要るときは worktree 内へ置き、そのパスを読むべきファイルの一覧に加える。

管理役が記入を確認してから、既存の `ask-opus.mjs` に `--role review`、`--request`、`--head` で渡す。テンプレートの展開と記入は管理役が行う。

通常は 200KiB の上限を差分にだけ掛け、差分が 200KiB を超えるときは PR を分ける。ask-opus.mjs は全差分の欄にある `<!-- ask-opus:diff-begin -->` と `<!-- ask-opus:diff-end -->` の行の間だけを数える。全差分は区切り行の内側にだけ貼り、外側に差分を置かない。区切り行はインデントや後ろの空白を付けずに、それぞれ 1 行で置き、消したり複製したりしない。区切り行が 1 組そろっていない依頼は、依頼全体を 200KiB の上限で数える。これとは別に、依頼全体が 1MiB を超えると、工程によらず ask-opus.mjs は起動前に拒む。1 PR に 1 依頼とし、工程ごとに分けた並列依頼はしない。

[ADR 0006 の段階受入・最終レビュー](../../../../docs/adr/0006-standing-approval-for-autonomous-delivery.md#統合専用ブランチへの段階受入と最終レビュー採用2026-11-01)は、2026-11-01 の利用者の規則案 A の承認を受けて採用した。出典・対象ブランチ・分割計画は同節に記録する。規則変更 PR #260 が必須 CI・独立レビューを経て main へマージされるまで、累積最終レビューのファイル形式を使わない。通常 PR と各段 PR は引き続き全差分を依頼へ貼り、各段 PR は全差分 200KiB 以内と最新 head のレビューを求める。

規則変更 PR #260 の main マージ後、明示承認された計画に基づく累積最終 PR の全差分が 200KiB を超える場合だけ、全差分の提供を worktree 内のファイル群に替えられる。全原文を改変・欠落なく保存し、順に連結した原文が比較コマンドの全出力と一致することを確かめる。全パス・順序・範囲の索引と各段レビュー済み範囲との対応をこの依頼に載せる。以下の全差分欄には形式を「明示承認済み累積最終・ファイル形式」と記し、原文を貼ったと偽らず、その索引を載せる（コードフェンスは `text` にする）。区切り行は一組のまま保ち、原文の内容には置換をかけない。ツールの上限・設定は変えず、依頼全体の 1MiB を含む現行上限に収める。通常規則へこの例外を流用しない。

## レビューへの依頼

上記 head の差分を受入条件と照合し、要件との一致、過剰設計、無関係な変更、境界条件、テストや品質設定の弱体化を確認する。実装担当の完了宣言や、古い head の検証・レビューを、対象 head の合格根拠にしない。

採用済みの承認累積最終 PR では、設計・実装・各段レビューとは別の新しいセッションが、最終 head の全累積差分、全 Requirement と相互作用をレビューする。ファイル形式なら索引にある全原文を全件 Read し、各パスの読取範囲と漏れの有無を報告する。一部が読めない、重大な指摘がある、受入条件が未達の場合は未受入とし、段階レビューや要約で代用しない。軽微な指摘の扱いは ADR 0006 のレビュー規則に従う。main への最終 PR の完了ゲート・全必須 CI・完成範囲に例外はない。

指摘ごとに重大度、対象ファイルと行、問題が起きる条件、根拠、修正すべき内容を回答する。対象 head と、重大・軽微・情報それぞれの指摘件数を明記する。材料不足や未実施の確認がある場合は、その内容と判定の限界も書く。

レビューの回数とマージ条件は ADR 0006 に従う。L2 では 1 回（指摘があれば修正後に 1 回だけ再レビュー）、L3 では最大 2 往復とし、マージ条件は重大な指摘がゼロであること。軽微な指摘は Issue に記録すればマージできるので、重大と軽微の区別を明確にする。
