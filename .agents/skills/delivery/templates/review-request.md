# Opus への最終レビュー依頼

管理役が実値に置き換えるのは、記入欄の `{{...}}` だけとする。引用する抜粋・差分・Requirement に含まれる `{{`・`}}` は変えない。該当しない欄には理由を書く。

記入欄を埋め終えてから、対象 head の `git show <head>:<path>` の出力から行番号付き抜粋と Requirement の全文を用意し、`git diff <base> <head>` で全差分を取得する。取得した本文と差分は変えずに依頼へ貼る。記入済みの依頼を専用 worktree の `.loomake/` 内へ保存し、引用した本文と差分が元の出力と一致することを確かめる。引用を貼った依頼全体に、プレースホルダーの置き換えを再び行わない。

追加の資料は必要な範囲に絞り、外部の資料も Read/Glob/Grep で読める worktree 内へ置く。パスだけで本文を代用せず、無関係なファイルの全文は加えない。

管理役が記入を確認してから、既存の `ask-opus.mjs` に `--role review`、`--request`、`--head` で渡す。テンプレートの展開と記入は管理役が行う。

依頼ファイルの上限は 200KiB。無関係な背景を省いても収まらない場合は、対象 PR や依頼する工程を分ける。必要な抜粋、Requirement の全文、レビュー対象の全差分を省いて上限に合わせない。

## 関連する Requirement の全文

管理役は関連する各 Requirement を、要件 ID、見出し、SHALL/MUST を含む本文、すべての Scenario、Source とともに貼る。差分仕様を使う場合は ADDED/MODIFIED/REMOVED の区分を示し、比較に必要な現行 Requirement も全文で載せる。開発の仕組みなどで Requirement がない場合は、その根拠と適用する文書の該当箇所を載せる。

````markdown
{{出典パス・要件 ID・差分の区分と、関連 Requirement の全文}}
````

## 対象ファイルの抜粋

管理役はファイルごとに、対象 head での相対パス、行番号、該当行の実際の内容を貼る。新規ファイルも含め、抜粋は判断に必要な該当行に絞る。レビュー対象の全差分は省かない。判断に必要な呼び出し元、利用側、既存テストも含め、必要に応じてこの欄を繰り返す。

```text
{{相対パス、対象 head、開始行と終了行}}
{{行番号付きの実抜粋}}
```

## レビューへの依頼

上記 head の差分を受入条件と照合し、要件との一致、過剰設計、無関係な変更、境界条件、テストや品質設定の弱体化を確認する。実装担当の完了宣言や、古い head の検証・レビューを、対象 head の合格根拠にしない。

指摘ごとに重大度、対象ファイルと行、問題が起きる条件、根拠、修正すべき内容を回答する。対象 head と、重大・軽微・情報それぞれの指摘件数を明記する。材料不足や未実施の確認がある場合は、その内容と判定の限界も書く。

最終レビューは最新のマージ対象 head で全重大度の指摘ゼロになるまで繰り返す。差分が変わった場合は、新しい head を新しいセッションで再レビューする。同じ指摘が 3 回連続で再出現したら管理役が Issue に記録し、修正とレビューを続ける。Issue 化だけで指摘を解消済みとは扱わない。
