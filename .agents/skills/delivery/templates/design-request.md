# Opus への設計依頼

管理役が実値に置き換えるのは、記入欄の `{{...}}` だけとする。引用する抜粋や Requirement に含まれる `{{`・`}}` は変えない。該当しない欄には理由を書く。

記入欄を埋め終えてから、対象 head の `git show <head>:<path>` の出力から行番号付き抜粋と Requirement の全文を用意し、取得した本文を変えずに依頼へ貼る。記入済みの依頼を専用 worktree の `.loomake/` 内へ保存し、引用した本文が元の出力と一致することを確かめる。引用を貼った依頼全体に、プレースホルダーの置き換えを再び行わない。

追加の資料は必要な範囲に絞り、外部の資料も Read/Glob/Grep で読める worktree 内へ置く。パスだけで本文を代用せず、無関係なファイルの全文は加えない。

管理役が記入を確認してから、既存の `ask-opus.mjs` に `--role design`、`--request`、`--head` で渡す。テンプレートの展開と記入は管理役が行う。

依頼ファイルの上限は 200KiB。無関係な背景を省いても収まらない場合は、対象 PR や依頼する工程を分ける。必要な抜粋や Requirement の全文を省いて上限に合わせない。

| 項目 | 管理役が記入する内容 |

| worktree | {{専用 worktree の実パス}} |

Opus は最初に上記の規約を読み、Read/Glob/Grep だけで設計する。ファイル変更やコマンド実行は行わない。以下の材料が不足している場合は、不足する箇所と設計への影響を示す。

## 関連する Requirement の全文

管理役は関連する各 Requirement を、要件 ID、見出し、SHALL/MUST を含む本文、すべての Scenario、Source とともに貼る。差分仕様を使う場合は ADDED/MODIFIED/REMOVED の区分を示し、比較に必要な現行 Requirement も全文で載せる。開発の仕組みなどで Requirement がない場合は、その根拠と適用する文書の該当箇所を載せる。

````markdown
{{出典パス・要件 ID・差分の区分と、関連 Requirement の全文}}
````

## 対象ファイルの抜粋

管理役はファイルごとに、対象 head での相対パス、行番号、該当行の実際の内容を貼る。新規ファイルも含め、抜粋は判断に必要な該当行に絞る。判断に必要な呼び出し元、利用側、既存テストも含め、必要に応じてこの欄を繰り返す。

```text
{{相対パス、対象 head、開始行と終了行}}
{{行番号付きの実抜粋}}
```

## 設計成果物への依頼

目的、範囲、対象外、前提、未決事項を整理し、受入条件ごとの実装方針・テスト案・確認方法・変更対象を回答する。未決事項は確定事項と分け、確認事項の ID、選択肢、おすすめと理由、影響を示す。実装担当が作業を始めるために不足する材料があれば明記する。
